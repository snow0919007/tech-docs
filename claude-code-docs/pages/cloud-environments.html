                    配置云环境

                    为 Claude Code 云端会话配置云环境：网络访问级别、环境变量、设置脚本和环境缓存。

                    说明

                    云环境适用于云端会话，这些会话在 Pro、Max、Ultra 和 Team 计划上可用，以及具有高级席位或 Chat + Claude Code 席位的 Enterprise 用户。

                    每个云端会话都在云环境中运行。您可以配置环境以允许或拒绝网络访问、为会话设置环境变量、存储会话使用但无法看到的网络密钥，以及在 Claude 开始工作前运行设置脚本。

                    相同的环境适用于您启动云端会话的任何地方：

                    • Desktop 应用
                    • Claude 移动应用
                    • 浏览器中的 claude.ai/code
                    • 终端中搭配 claude --cloud
                    • 云端定时任务
                    • Claude Tag

                    这些使用入口中的每一个也可以路由到自托管环境。可用性和限制涵盖了当 Claude Tag 会话在其中运行时 Claude 还不能使用的内容。

                    说明

                    Remote Control 会话将网页和移动界面连接到您自己机器上的会话，该会话使用您机器的网络和文件，而不是云环境。要选择 Claude Tag 频道使用的环境，请参阅设置 Claude Tag 频道使用的环境。

                    Default 环境

                    如果您还没有环境，引导设置会为您设置 Default 环境。具体方式取决于您在哪里进行引导：

                    • CLI 流程（例如 /web-setup）：为您创建 Default
                    • Pro、Max 和 Ultra 上的网页引导：自动为您提供 Default
                    • Team 和 Enterprise 上的网页引导：显示 Create your first cloud environment 表单，除非所有者已启用快速设置；保持表单的默认值并点击 Create & finish 以获得相同的 Default 环境

                    Default 本身不带有任何配置：

                    • Trusted 网络访问：会话可以访问包注册表和其他允许列表中的域，但无法通过会话的网络访问其他任何内容。
                    • 无其他配置：Default 不定义任何环境变量或设置脚本，因此会话只以预安装的工具开始。

                    只有 Default 可用时，每个会话都在其中运行。当您有多个环境时，会话会按界面选择一个：

                    • 在网页、Desktop 应用和移动应用上，会话使用选择器中显示的环境。当您尚未选择时，所有者设置的组织默认值会填入选择。线程在项目中使用项目设置中设置的环境。
                    • 从 CLI，Claude Code 使用您的 /remote-env 选择，或在您的列表中有一个 Anthropic 托管环境时回退到该环境，否则回退到您列表中第一个不是桥接环境的环境，即 Remote Control 注册的条目，用于代表您自己的机器而不是云环境。对于自托管环境，在分派会话时使用其 ccpool_ ID 传递 --environment <environment-id> 会覆盖该调用的 /remote-env 选择和回退。Claude Code 拒绝传递给该标志的 Anthropic 托管 env_ ID，因此请使用 /remote-env 来定位这些。该标志需要 Claude Code v2.1.224 或更高版本。

                    当默认环境不够用时，请配置环境：当 Claude 需要访问默认允许列表之外的域、需要为其会话设置环境变量，或需要在开始工作前安装依赖项时。

                    配置您的环境

                    在 claude.ai/code 上启动新会话的页面中，通过消息框下方的环境选择器添加、编辑和归档环境。要进入该页面，请完成网页入门引导。对于桌面应用，请参阅云端会话。您创建的环境是您账户的个人环境；由所有者创建的共享环境会与它们一起出现在选择器中。查看已安装的工具，了解无需任何配置即可使用的工具。

                    选择器仅在您发送新会话的第一条消息之前显示。要编辑您自己正在运行的云端会话的环境，请选择顶部会话标题后的插入符号，然后选择 Edit cloud environment。

                    1. 打开环境选择器

                    在新会话页面上，选择消息框下方行中的第一个控件。

                    2. 添加或编辑环境

                    • 添加环境：选择菜单底部的 New environment 以打开 New environment 对话框。填写表单并选择 Add environment。随后您的新会话将使用您添加的环境。
                    • 编辑环境：在 Cloud 下找到该环境所在的行。如果 Cloud 只是单独一行，请选择它以打开列表。如果您的环境未列在 Cloud 下，请选择该标题下的 More 行。悬停在该环境的行上，然后选择其右侧出现的设置图标以打开其对话框。

                    当您添加环境或编辑您自己的环境时，选择对话框中的 Network access、Setup script 或 Environment variables 行以打开相应设置。完成最后一项更改后，对于新环境请使用 Add environment 保存，对于现有环境请使用 Save changes 保存。要存储会话可以使用但无法看到的密钥，请参阅添加网络机密。

                    设置环境变量

                    环境变量使用 .env 格式，每行一个 KEY=value 对。普通值不需要引号，如果您用匹配的一对引号引用一个值，引号不会成为该值的一部分。跨越多行或包含 # 的值需要加引号：在未加引号的值中，# 会开始注释，该行的其余部分会被丢弃。

                    以下示例定义了三个变量。

                    text
                    NODE_ENV=development
LOG_LEVEL=debug
DATABASE_URL=postgres://localhost:5432/myapp

                    会话会将环境的值读入普通环境变量中，Claude 运行的任何命令都可以读取这些变量，OTEL_* 变量除外。Claude Code 使用这些变量进行自己的遥测导出，不会将它们传递给它运行的命令。

                    在 Anthropic 托管的环境中，会话在创建时读取环境的值，之后每次 Claude Code 在会话的 VM 中启动时也会再次读取，这发生在两种情况下：

                    • VM 在空闲后被恢复：在几分钟没有活动后，会话的 VM 会暂停，其文件会被保存。您的下一条消息会恢复同一个 VM 并再次启动 Claude Code。
                    • VM 被回收并被重建：如果暂停的 VM 已经被回收，重新打开会话会配置一个新的 VM。

                    编辑、添加或删除变量后，Anthropic 托管环境中的现有会话会保持它最后读取的值，直到其 VM 下次被恢复或重建，此后才使用您的更改。会话空闲后其 VM 会自动暂停，您无法手动暂停它。要立即使用新值，请要求 Claude 在它运行的命令上设置该值，例如 LOG_LEVEL=trace npm test，或启动一个新会话。

                    云端会话在启动时也会自行设置一些变量。对于 CLAUDE_AUTOCOMPACT_PCT_OVERRIDE，会话设置的值会覆盖您在这里添加的值，因此在这里添加该键没有效果。

                    使用该环境的任何人都可以读取这些值。在 Anthropic 托管的环境中，对于 Agent 代理可以附加到请求中的密钥，请改用网络机密。永远不会获得机密的请求在该处列出。

                    添加网络机密

                    网络机密是您存储在云环境中的 API 密钥或令牌，使 Claude 可以从该环境中的任何会话调用该 API，而无需看到密钥。每个请求离开会话的 VM 后，Anthropic 的 Agent 代理会将密钥添加到发往您所列主机的请求中，因此密钥本身始终位于 VM 之外。

                    网络机密适用于 Pro、Max、Ultra、Team 和 Enterprise 计划。要确认您是否可以自行添加，请参阅要求。

                    要求

                    以下要求决定您是否可以添加机密，以及添加后 Agent 代理是否可以使用它：

                    • Role：在所有计划上，无论您的角色如何，您都可以在自己的环境中添加和删除机密。在 Team 和 Enterprise 上，所有者在您的 claude.ai 组织中持有组织管理员角色，管理员（Admin）不持有，这会改变您在以下情况下看到的内容：
                    • 您自己的环境：没有组织管理员角色时，Add secret 会打开一个简化表单
                    • 共享环境：所有者从管理设置中添加和删除其机密。没有组织管理员角色时，请让所有者添加机密，因为该环境的对话框中没有 Network secrets 部分
                    • Environment type：一个已存在的 Anthropic 托管云环境。自托管环境没有网络机密
                    • API reachability：API 接受来自互联网的连接，因为请求从 Anthropic 的网络发出
                    • Encryption keys：如果您的组织使用客户管理的加密密钥，则无法保存网络机密

                    添加机密

                    机密需要逐个添加。要更改机密的主机或值，请将其删除后重新添加。

                    要向共享环境添加机密，请从管理设置中的 Cloud environments 页面打开该环境进行编辑，然后在其 Network secrets 部分从步骤 2 继续。如果您使用的是 Team 或 Enterprise 计划且不持有组织管理员角色，请在您自己的环境中执行步骤 1，然后填写简化表单。

                    1. 打开环境的网络机密

                    在 claude.ai/code 打开环境进行编辑。在 Edit cloud environment 对话框中，选择 Network secrets 行。您会看到环境中已有的机密，每个机密都附有其适用的主机。

                    2. 添加机密

                    选择 Add secret（在管理设置中标记为 Add）并填写表单。对于在请求头中传输的 API 密钥，保留默认的 Secret type，即 Bearer，并填写以下字段：

                    • Name：机密的标签，例如 Internal billing API
                    • Allowed websites：API 的主机，例如 api.example.com。前导 *. 匹配所有子域
                    • Custom headers：用于携带密钥的请求头占一行。该行默认以 Authorization 作为请求头的 Name，以 Bearer 作为其 Prefix；将密钥本身粘贴为 Value。对于接受裸值的请求头（如 X-Api-Key），请更改名称并清除前缀

                    对于以其他方式进行身份验证的 API，请选择不同的 Secret type。该列表与 Claude Tag（适用于 Team 和 Enterprise 计划的 Slack 集成）为 connections 提供的列表相同。

                    3. 保存机密

                    选择 Add。机密会连同其主机一起出现在列表中，无需点击对话框的 Save changes 按钮即已保存。保存后您无法再次查看该值。

                    要确认机密是否有效，请在该环境中启动会话并让 Claude 调用 API，例如使用 curl。API 的响应就如同请求中带有密钥一样，而密钥不会出现在会话的环境变量或任何文件中。如果列表将某个机密标记为 Not sent，其下方的说明会解释原因和处理方法。两个主机重叠但不完全匹配的机密不会显示标记，而 Agent 代理只会发送其中一个。

                    在没有组织管理员角色的情况下添加机密

                    如果您使用的是 Team 或 Enterprise 计划且不持有组织管理员角色，Add secret 表单只接受针对一个主机的一个机密。选择您环境的 Network secrets 行，然后选择 Add secret。填写以下字段，然后选择表单中的 Add secret 按钮：

                    • Host：获得该机密的唯一主机，例如 api.example.com。该表单不接受 *. 通配符
                    • Name：机密的可选标签
                    • Secret type：对于在请求头中传输的密钥选择 Token，或选择 Username and password。对于令牌，请将密钥粘贴为 Value

                    哪些请求会获得机密

                    当请求的主机与您在某个机密上列出的主机匹配时，Agent 代理会将该机密附加到请求中。即使环境的网络访问级别原本不允许访问这些主机，会话也可以访问它们，但永远不会获得机密的主机除外。机密适用于在该环境中运行的每个会话，无论由谁启动，直到您将其删除。

                    永远不会获得机密的请求

                    Agent 代理永远不会将您添加的机密附加到以下请求：

                    • GitHub：GitHub 代理会代为对发往 GitHub 的请求进行身份验证，因此您无需为其设置网络机密
                    • Anthropic API 和公共包注册表：api.anthropic.com、registry.npmjs.org、jsr.io、npm.jsr.io、pypi.org、files.pythonhosted.org、index.crates.io 和 proxy.golang.org
                    • 设置脚本请求：Claude Code 在启动时才连接到 Agent 代理，此时设置脚本已经运行完毕
                    • Claude Code 的遥测导出：Claude Code 自行发送其遥测导出，而不是通过它运行的命令发送，该请求不会经过 Agent 代理

                    从 CLI 选择环境

                    在终端中运行 /remote-env，为您从 CLI 创建的云端会话（例如 claude --cloud）选择默认环境。该命令会打开现有环境的选择器，并将您的选择保存到用户设置中的 remote.defaultEnvironmentId 键，因此它适用于您机器上的每个项目，直到您更改它为止，除非在更高优先级的设置层级（例如仓库的项目设置）中设置了相同的键。

                    自托管环境 ID 的形式为 ccpool_...，遵循更严格的来源规则。查看 remote.defaultEnvironmentId，了解 Claude Code 会从哪些设置层级采用该值。

                    /remote-env 仅设置默认值：它不会启动会话，也不能添加或编辑环境。请从环境选择器管理环境。

                    归档环境

                    要归档您自己的某个环境，请打开它进行编辑，选择 Archive environment 并确认。如果该环境已与您的组织共享，则改由所有者从管理设置中的 Cloud environments 页面将其归档，因此除非您本身就是所有者，否则请联系所有者。

                    归档影响新会话，不影响运行中的会话：

                    • 已经在环境中运行的会话会继续工作。
                    • 环境会从选择器和 /remote-env 中消失，因此您无法为新会话选择它。
                    • 环境中的网络机密在其正在运行的会话中仍保持附加状态。请在归档前删除不再需要的机密。
                    • 在任何使用入口上都无法在已归档的环境中启动新会话：
                    • 保存的 CLI 默认值：如果该环境是您保存的 CLI 默认值，当您的列表中有 Anthropic 托管的环境时，Claude Code 会在该环境中启动 CLI 云端会话。否则，会在列表中第一个不是 Remote Control bridge 环境的环境中启动。
                    • 显式配置：任何显式配置了该环境的内容，例如云端定时任务，都无法在其中启动新会话。请将其指向另一个环境。

                    当您不再需要某个 Anthropic 托管的环境时，请将其归档。环境对话框和 Cloud environments 管理页面都没有删除 Anthropic 托管环境的选项。如果该环境是自托管的，所有者可以从管理设置中的 Cloud environments 页面将其删除。如果您不是所有者，请联系所有者将其删除。

                    组织共享环境

                    在 Team 和 Enterprise 计划上，所有者可以创建与组织每个成员共享的云环境。同一角色管理 Cloud environments 管理页面上的其他所有内容，包括自托管环境；管理员（Admin）角色无法打开该页面。可以打开该页面的完整角色列表与管理服务器托管设置的角色列表相同。

                    共享环境出现在每个成员的环境选择器中的 Organization 标题下，位于成员自己在 Personal 下的环境之后，因此团队可以统一使用一套配置，而无需每个成员各自重新创建。在那里选择共享环境的设置图标，会为每个成员（包括所有者）打开其配置的只读摘要。

                    所有者可以通过以下两种方式之一使环境对组织可用：

                    • 创建共享环境：使用管理设置中的 Cloud environments 页面，所有者也在该页面编辑和归档共享环境。每个共享环境都有一个名称、一个网络访问级别、.env 格式的环境变量和一个设置脚本。
                    • 共享个人环境：在环境选择器中打开您自己的某个环境进行编辑，然后从 Who can use it 行共享它。环境会保留其 ID，因此已经使用它的会话和定时任务不受影响，每个成员随后都可以看到它并在其中启动会话。

                    所有者在 claude.ai/admin-settings/claude-code 单独选择组织的默认环境。

                    要为共享环境的会话提供其无法读取的密钥，请在 Cloud environments 页面编辑该环境时添加网络机密。请勿在其变量中包含机密信息，因为每个成员的会话都会读取这些变量。

                    设置 Claude Tag 频道使用的环境

                    在 Claude Tag 频道中，Claude 以您组织的共享身份工作，而不是以任何成员的身份工作，因此频道会话仅使用组织级别的环境，即共享环境或自托管环境。要为频道提供未预安装的工具链（例如 .NET），所有者可以从 Cloud environments 管理页面创建一个共享环境，并使用设置脚本安装该工具链。通过以下两种方式之一将频道指向某个环境：

                    • 在 claude.ai/admin-settings/claude-code 将共享环境或自托管环境设置为组织的默认环境。
                    • 在 Claude Tag 管理设置中将某个环境固定到频道。

                    网络访问

                    每个环境都设置一个网络访问级别，控制其会话可以进行的出站连接。默认级别 Trusted 允许包注册表和其他允许列表中的域；Custom 采用您自己的域列表。

                    要更改环境的网络访问，打开它进行编辑并在对话框中使用 Network access 选择器。共享环境在那里以只读方式打开，因此 Owner 改为从管理设置中的 Cloud environments 页面更改其网络访问。打开选择器的控件出现在Default 环境下列出的应用使用入口上，以及云端定时任务编辑器中。个人环境在您的 claude.ai 账户设置中没有单独的页面。

                    当您更改 Anthropic 托管环境的网络访问时，其现有会话在约一分钟内遵循新设置，用于通过会话的网络允许列表的请求。您无需启动新会话。

                    说明

                    您在会话或定时任务上启用的 MCP 连接器无需将其主机添加到 Allowed domains，因为连接器流量通过 Anthropic 的服务器而不是会话的网络传输。这依赖于安全性和隔离下提到的同一条通往 Anthropic 的通道。关闭任何您不需要的连接器，以限制 Claude 可以访问的工具。

                    访问级别

                    Network access 字段在环境对话框中采用以下四个级别之一：

                    级别 出站连接
                    None 通过会话的网络没有出站网络访问
                    Trusted 仅限允许列表中的域：包注册表、GitHub、云 SDK
                    Full 任何域
                    Custom 您自己的允许列表，可选择包含默认值

                    • GitHub，通过其单独的代理
                    • 您启用的 MCP 连接器，其流量通过 Anthropic 的服务器传输
                    • 您在环境的网络密钥上列出的主机，除了永远不会获得该密钥的主机
                    • Anthropic API，用于 Claude Code 自己的请求，即使在 None 下也是如此，如安全性和隔离下所述

                    GitHub 代理

                    在 Anthropic 托管的环境中，所有 GitHub 操作都经过专用代理，使您的真实 GitHub 凭据保留在会话的 VM 之外，独立于环境的访问级别。自托管环境中的会话使用您的部署提供的凭据进行 git 操作身份验证；配置 git涵盖了选项，包括按会话生成的凭据和选择加入此同一代理。代理提供：

                    • Git 凭据：VM 内的 git 客户端使用范围受限的凭据，代理验证并将其交换为您的实际 GitHub 令牌。
                    • API 请求：来自内置 GitHub 工具的请求，以及来自 proxy-injected 占位符下的 gh 的请求，会在替换为您的真实凭据后发出。
                    • 推送限制：代理会拒绝分支删除，以及推送分支以外的任何内容（例如标签）。它不限制推送可以更新哪些分支。如需限制，请在 GitHub 上使用分支保护规则或规则集。
                    • 仓库范围：代理为附加到会话的仓库处理 GitHub API 请求。针对其他仓库的 API 请求会收到 403，其消息以 GitHub access to 开头并包含 is not enabled for this session。当仓库未附加时，您通过 github.com/{owner}/{repo}/archive/ 或 codeload.github.com URL 获取的源代码归档也会收到相同的 403，即使是公开仓库也是如此。
                    • GraphQL 限制：代理会拒绝发往 GitHub GraphQL 端点的请求，返回 403，其消息以 GitHub GraphQL is not available from Claude Code sessions 开头，并指明 REST 回退方式 gh api repos/{owner}/{repo}/...。使用 GraphQL 的 gh 子命令（例如 gh pr 和 gh issue）也会收到相同的 403。无论您提供的凭据如何，限制都适用于通过代理的每个请求，因此您设置的 GH_TOKEN 会收到相同的 403。Claude 无法通过代理访问仅存在于 GraphQL 中的 GitHub API，例如 Projects v2。

                    来自公开仓库的已提交文件通过 raw.githubusercontent.com 到达，改由安全代理处理。该域在默认 Trusted 列表中，因此除非环境的访问级别排除它，否则这些文件保持可访问。

                    安全代理

                    Anthropic 托管环境中的云端会话在 HTTP/HTTPS 网络代理后面运行，用于安全和滥用防范目的；在自托管环境中，出站流量通过您自己的网络边界离开。来自 Anthropic 托管会话的所有出站互联网流量都经过此代理，它提供：

                    • 防范恶意请求
                    • 速率限制和滥用防范

                    使用 GitHub 问题和 Pull Request

                    云端会话包括内置 GitHub 工具，让 Claude 无需任何设置即可读取问题、列出 Pull Request、获取 diff 和发布评论。这些工具通过 GitHub 代理，使用您在 GitHub 身份验证选项下配置的任何方法进行身份验证，因此您的令牌永远不会进入容器。

                    您可以在环境设置中自己设置 GH_TOKEN 或 GITHUB_TOKEN，或者两者都不设置，让 GitHub 代理为您进行身份验证：

                    • 如果您设置了令牌，它会原封不动地传递到容器中，因此您的脚本和 GitHub 的 gh CLI 会直接使用它。
                    • 如果您都不设置，且由 GitHub 代理为您的会话处理身份验证，这两个变量在 Claude 运行的命令中读取为占位符字符串 proxy-injected，代理在出站 GitHub 请求上替换为您的真实凭据。针对已附加仓库的 gh api 调用无需您自己的令牌即可工作，但直接读取 GITHUB_TOKEN 的脚本会得到占位符，而不是可用的令牌。

                    您设置的令牌是普通环境变量，因此使用环境的任何人都可以读取它；代理路径将凭据保留在环境配置和会话 VM 之外。

                    要检查哪种情况适用于您的会话，请让 Claude 运行 echo $GH_TOKEN。

                    GitHub 的 gh CLI 已预安装。如果您需要内置工具未涵盖的 GitHub 操作，请让 Claude 使用 gh api 调用 REST API。使用 REST API 的 gh 子命令（例如 gh workflow list）也可以工作。代理会拒绝使用 GraphQL 的子命令，例如 gh pr 和 gh issue。gh 会自动读取 GH_TOKEN，因此您不需要运行 gh auth login。

                    将输出链接回会话

                    每个云端会话在 claude.ai 上都有一个会话记录 URL，会话可以从 CLAUDE_CODE_REMOTE_SESSION_ID 环境变量读取自己的 ID。使用它在 PR 正文、提交信息、Slack 帖子或生成的报告中放置可追溯的链接，以便审阅者可以打开生成它们的运行。

                    Claude 在云端会话中创建的提交包括 Claude-Session: <url> git 尾注，PR 正文在单独一行包括会话 URL。要省略尾注和 PR 正文链接，请将 attribution.sessionUrl 设置为 false。

                    要在提交或 PR 以外的内容中包含会话链接，例如 Claude 发布的 Slack 消息或它编写的报告文件，请让 Claude 运行以下命令并使用其输出。该命令将环境变量值中的 cse_ 前缀转换为会话记录 URL 预期的 session_ 前缀：

                    bash
                    echo "https://claude.ai/code/${CLAUDE_CODE_REMOTE_SESSION_ID/#cse_/session_}"

                    资源限制

                    时间限制

                    在 Anthropic 托管的环境中，这些时间限制适用于云端会话中的长时间运行的工作，例如构建、安装或测试运行。每个条目链接到定义该限制的部分。

                    • Claude 运行的命令：云环境不设置自己的命令超时时间，因此 Bash 工具的默认值适用。Claude 默认为前台命令等待 2 分钟，最多可以要求 10 分钟。

                    当命令达到其超时时，Claude Code 将其移到后台，而不是停止它，除非命令以 sleep 开头。以这种方式移动的命令可以继续运行最多 30 分钟，然后 Claude Code 在其后台时间限制处停止它。将 BASH_DEFAULT_TIMEOUT_MS 设置为 1800000 毫秒以上会延长该限制以及前台默认值。
                    * SessionStart hook：Claude Code 在 600 秒后取消 command hook，除非您在 hook 条目上设置 timeout（以秒为单位）。Claude Code 不会对您使用 async: true 运行的 hook 强制执行超时。
                    * 设置脚本：花费超过大约五分钟的脚本不会被缓存。脚本要求涵盖如何保持在该时间以下。
                    * 空闲会话：在几分钟没有活动后，会话的 VM 会暂停并保存其文件，暂停的 VM 之后可能会被回收。设置环境变量描述会话在每种情况下会获取什么，环境已过期涵盖如何重新打开 VM 被回收的会话。

                    要为环境的会话提高命令超时时间，请将 BASH_DEFAULT_TIMEOUT_MS 和 BASH_MAX_TIMEOUT_MS 添加到其环境变量。两者都采用毫秒。例如，BASH_DEFAULT_TIMEOUT_MS=600000 使 10 分钟成为默认值。

                    设置脚本

                    设置脚本是一个 Bash 脚本，在新的云会话启动时运行，在 Claude Code 启动之前运行。使用设置脚本来安装依赖项、配置工具，或获取会话需要但未预安装的任何内容。

                    脚本以 root 身份在 Ubuntu 24.04 上运行，因此 apt install 和大多数语言包管理器都能工作。

                    添加设置脚本

                    要为您自己的环境添加设置脚本，可以直接输入或粘贴脚本，也可以加载 setup.sh 等文本文件。添加或编辑环境，然后选择 Setup script 行。在打开的框中输入脚本，或选择 Choose file，用不超过 64 KB 的文件文本替换框中的内容。然后选择 Add environment 或 Save changes。

                    此示例安装 ShellCheck，它不是预安装的。

                    bash
                    #!/bin/bash
apt update && apt install -y shellcheck

                    脚本要求

                    设置脚本有四个需要考虑的约束：

                    • 以零退出：如果脚本以非零状态结束，会话将无法启动。在非关键命令后附加 || true，以便间歇性安装失败不会阻止会话。
                    • 在五分钟内完成：将脚本的总运行时间保持在大约五分钟以内，以便环境缓存可以建立。当设置耗时超过五分钟时，环境不会被缓存。使用 & 和 wait 并行运行独立的安装，并将任何无法容纳的单个下载移至 SessionStart hook，在后台启动它。如果新会话在设置期间停滞或失败，请参阅新会话在设置期间挂起或超时。
                    • 安装需要网络访问：包安装需要连接到注册表。默认的 Trusted 级别涵盖常见包注册表，包括 npm、PyPI、RubyGems 和 crates.io；使用 None 网络访问时，安装会失败。
                    • 环境的变量尚未设置：脚本在会话设置环境的环境变量之前运行。请在脚本本身中设置脚本所需的任何值。

                    环境缓存

                    设置脚本在您第一次在环境中启动会话时运行。当设置在大约五分钟内完成时，Anthropic 会对文件系统进行快照，并将该快照重用作后续会话的起点。新会话以您的依赖项、工具和 Docker 镜像已在磁盘上的状态开始，并跳过设置脚本步骤。即使脚本安装大型工具链或拉取容器镜像，这也能保持启动速度快。如果设置耗时超过大约五分钟，环境不会被缓存。

                    缓存是文件系统快照，因此它会保留设置脚本写入磁盘的内容，并丢失任何仅在运行中的内容。您安装的包、您拉取的 Docker 镜像和您写入的文件都会保留。脚本启动的数据库、docker compose up 堆栈或任何其他后台进程不会保留；请通过询问 Claude 或使用 SessionStart hook 在每个会话中启动这些。

                    当您更改环境的设置脚本或允许的网络主机时，以及当缓存在大约七天后到期时，设置脚本会再次运行以重建缓存。在 Anthropic 托管环境中，当会话的 VM 在空闲后恢复时，设置脚本不会运行，因此对脚本的更改仅在其 VM 被回收并重建时才会到达现有会话。要立即应用更改，请在会话中运行命令或启动新会话。

                    您不需要自己启用缓存或管理快照。

                    设置脚本与 SessionStart hooks

                    使用设置脚本来配备 VM 本身：未预安装的工具链和 CLI 工具。使用 SessionStart hook 进行应在各处运行的项目设置，包括云端和本地，例如 npm install。

                    设置脚本和 SessionStart hooks 在云会话启动时按固定顺序运行。下表比较了您在哪里配置它们、何时运行以及在哪里运行。

                    设置脚本 SessionStart hooks
                    您在哪里配置它们 claude.ai/code 的环境对话框，以及共享环境的 Cloud environments 管理页面 设置文件，例如您的存储库的 .claude/settings.json；请参阅您的设置中会保留的内容，了解哪些文件会到达云会话
                    它们何时运行 在 Claude Code 启动之前，当存在缓存环境时跳过 在 Claude Code 启动后，在每个会话（包括已恢复的会话）上
                    它们在哪里运行 仅限云会话 本地和云会话

                    如果您在用户级 ~/.claude/settings.json 中有 SessionStart hooks，不要期望它们在云端生效。用户级设置保留在您的机器上。其他 hooks 运行的位置取决于会话运行的位置：

                    • Anthropic 托管环境：Claude Code 运行来自您组织的服务器管理的设置的 hook，并且在项目线程之外，还运行来自仓库的 hook。Claude Tag 会话不会接收服务器管理的设置，因此来自服务器管理的设置的 hook 不会在那里运行。
                    • 自托管环境：Claude Code 还运行运行程序主机的 ~/.claude/ 中的运行程序操作员播种的 hooks，以及运行程序镜像的托管设置文件中的 hooks，当该文件是 Claude Code 应用的托管源之一时。

                    使用 SessionStart hook 安装依赖项

                    要仅在项目线程之外的云端会话中安装依赖项，请将 SessionStart hook 与检查其运行位置的脚本配对。

                    首先，将 SessionStart hook 添加到您的存储库的 .claude/settings.json。此配置告诉 Claude Code 在会话启动或恢复时运行存储库中的 scripts/install_pkgs.sh：

                    json
                    {
  "hooks": {
    "SessionStart": [
      {
        "matcher": "startup|resume",
        "hooks": [
          {
            "type": "command",
            "command": "bash \"$CLAUDE_PROJECT_DIR\"/scripts/install_pkgs.sh"
          }
        ]
      }
    ]
  }
}

                    matcher 将 hook 限制为 startup 和 resume 事件，$CLAUDE_PROJECT_DIR 解析为存储库根目录，因此无论会话的工作目录是什么，hook 都能找到脚本。

                    接下来，在 scripts/install_pkgs.sh 创建脚本。它在云端之外立即退出，否则安装您的依赖项。当 package.json、package-lock.json 和脚本本身自上次成功安装以来均未更改时，它会跳过 npm install：

                    bash
                    #!/bin/bash

if [ "$CLAUDE_CODE_REMOTE" != "true" ]; then
  exit 0
fi

cd "$CLAUDE_PROJECT_DIR" || exit 1
hashes=node_modules/.install_pkgs.sha256

if ! sha256sum --check --status "$hashes" 2>/dev/null; then
  # Delete the old hashes first, so a failed install runs again next time
  rm -f "$hashes"
  if npm install; then
    sha256sum scripts/install_pkgs.sh package.json package-lock.json > "$hashes" || rm -f "$hashes"
  fi
fi

# pip skips requirements that are already satisfied
pip install -r requirements.txt
exit 0

                    CLAUDE_CODE_REMOTE 检查是将安装限制在云会话的关键：会话 VM 的环境将该变量设置为 true，在本地永远不会是 true，因此在您的笔记本电脑上，脚本会在安装任何内容之前退出。

                    要确认 npm install 已成功，请启动一个云端会话，并让 Claude 显示 node_modules/.install_pkgs.sha256。该文件列出了这三个文件各自的哈希值。如果该文件不存在，请让 Claude 运行 npm install 并报告错误。

                    说明

                    如果 npm install 会读取其他文件，例如工作区的 package.json、.npmrc 或您的 postinstall 脚本的输入，请将它们添加到保存哈希值的 sha256sum 命令中。否则，在其中某个文件更改后，您仍会保留旧的包。

                    云会话中的限制

                    SessionStart hooks 在云端的行为与本地相同，但有以下注意事项：

                    • 每个会话一个仓库：在 Anthropic 托管环境中，具有多个仓库的会话不会从任何仓库的 .claude/settings.json 加载 hook，因此您在那里定义的 SessionStart hook 不会运行。请改为使用设置脚本为这些会话安装依赖项。对于自托管环境，请参阅适用哪个仓库的设置。
                    • 不适用于项目的云端线程：项目中的云端线程不会运行来自仓库 .claude/settings.json 的 hook，无论仓库数量多少。在 Anthropic 托管环境中，请使用设置脚本为线程安装依赖项。在自托管环境中，请改为使用运行程序主机设置中的 hook。
                    • 没有仅云端的范围：hooks 在本地和云会话中都运行。要跳过本地运行，请在 CLAUDE_CODE_REMOTE 环境变量不为 true 时提前退出，就像依赖项安装脚本所做的那样。
                    • 需要网络访问：安装命令需要连接到包注册表。如果您的环境使用 None 网络访问，这些 hooks 会失败。Trusted 下的默认允许列表涵盖 npm、PyPI、RubyGems 和 crates.io。
                    • 代理兼容性：在 Anthropic 托管环境中，所有出站流量都经过安全代理，某些包管理器无法与此代理正确配合工作；Bun 是一个已知的例子。在自托管环境中，出站流量改为经过您自己的网络边界。
                    • 增加启动延迟：hook 在每次会话启动或恢复时运行，不同于受益于环境缓存的设置脚本。请通过跳过已完成的工作来保持安装脚本快速，就像依赖项安装脚本所做的那样。

                    要自定义基础镜像，请使用设置脚本在提供的镜像上安装您需要的内容，或使用 docker compose 将您自己的镜像作为 Claude 旁边的容器运行。目前不支持完全替换基础镜像。
