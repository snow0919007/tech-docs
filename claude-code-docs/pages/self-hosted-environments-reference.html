                    自托管环境参考

                    自托管运行器和编排器的完整参考：CLI 标志、环境变量和 Prometheus 指标。

                    说明

                    自托管环境在 Team 和 Enterprise 计划上处于公开测试阶段；所有者通过在云环境管理页面上打开允许自托管环境来启用它们。本页面是标志和指标参考；有关设置，请参阅快速入门，有关舰队配方，请参阅部署到生产。

                    本页面是您在自托管环境中运行的两个进程的参考：运行器，它在您的主机上执行 Claude Code 云会话，以及可选的自动扩展编排器，它在会话队列时启动运行器。每个都有自己的标志表。两者都在 Linux 或 macOS 主机上运行，默认值如 /workspace 和 ~/.claude 假设。运行 claude self-hosted-runner --help 以获取已安装版本上的权威列表。

                    指标系列和一些 API 字段仍然使用 pool 来表示这些页面所称的环境；两个术语都指同一事物。环境 ID 是 pool_id 字段，形式为 ccpool_...：无论这些页面在哪里显示 pool 标识符，它都命名环境。CLI 标志和环境变量将其拼写为 environment，例如 --environment-secret-file；已弃用的 pool 拼写仍然有效，如--environment-secret-file 行所述。

                    Runner CLI 标志

                    大多数标志都有对应的环境变量。两者同时设置时，标志优先。时长类标志在 CLI 中以分钟或秒为单位，但对应的环境变量始终以毫秒为单位（由 _MS 后缀表示），而“默认值”列显示的是标志的单位：--exit-if-unused-min 10 等同于 SELF_HOSTED_RUNNER_IDLE_SHUTDOWN_MS=600000，而像 SELF_HOSTED_RUNNER_STARTUP_TIMEOUT_MS: "15" 这样的 Helm 值表示 15 毫秒，而不是默认的 15 分钟。

                    标志 环境变量 默认值 描述
                    --api-url <url> 无 https://api.anthropic.com API 基础 URL。仅在测试时覆盖。
                    --base-dir <path> SELF_HOSTED_RUNNER_BASE_DIR /workspace；在 Windows 上无默认值 用于仓库检出和每个会话工作目录的目录。runner 需要对此路径或其父目录具有写入权限。runner 在启动时创建该目录，若无法创建或写入该目录，则以 cannot create or write to base directory 退出。在 v2.1.225 之前，runner 在第一个会话启动时才创建该目录，因此不可用的路径会导致会话失败，而不是启动失败。在 Windows 上（Windows 不是受支持的 runner 主机）没有默认值：除非您传入该标志或设置该变量，否则 runner 会在启动时退出。在同一环境中的每个 runner 上使用相同的值。请参阅在各 runner 之间保持基础目录和容量一致。
                    --capacity <n> 无 1 此 runner 处理的最大并发会话数。所有会话都属于同一个已锁定的所有者。在同一环境中的每个 runner 上使用相同的值；请参阅在各 runner 之间保持基础目录和容量一致。
                    --client-label <label> SELF_HOSTED_RUNNER_CLIENT_LABEL 主机的主机名 runner 注册时发送的标签。runner 还会将其作为 claude_code_self_hosted_runner_info 的 client_label 标签进行报告。需要 Claude Code v2.1.248 或更高版本。
                    --configure-git SELF_HOSTED_RUNNER_CONFIGURE_GIT=1 关闭 在启动时写入全局 git 身份、启用 Anthropic 提交签名、打开 git push 协商，并安装用于追加 Co-authored-by: 尾注的提交钩子。push 协商需要 Claude Code v2.1.257 或更高版本。请参阅配置 git。
                    --confine-repo-settings <mode> SELF_HOSTED_RUNNER_CONFINE_REPO_SETTINGS warn 设置防护机制的模式：当仓库中已提交的设置试图授予该会话自身工作区之外的写入或读取权限、设置环境变量，或覆盖运维人员的沙箱或 hook 策略（例如 sandbox.enabled: false 或 disableAllHooks）时，该防护机制会标记该会话。默认值 warn 会记录违规并仍然启动会话，enforce 会拒绝该会话，off 则禁用扫描。请参阅加固您的部署。
                    --debug-token-dir <path> SELF_HOSTED_RUNNER_DEBUG_TOKEN_DIR 未设置 将有效令牌写入磁盘以供检查。仅用于调试；请勿在生产环境中使用。
                    --defer-shutdown-max-min <n> SELF_HOSTED_RUNNER_DEFER_SHUTDOWN_MAX_MS 0 收到第一个 SIGTERM 或 SIGINT 时，继续为已附加的会话提供服务而不是排空它们，然后在 N 分钟后释放仍附加的所有会话并退出。设置此项之前，请先调高主机的停止超时时间。请参阅将排空推迟到第一个信号之后。0 表示禁用。需要 Claude Code v2.1.238 或更高版本。
                    --drain-grace-sec <n> SELF_HOSTED_RUNNER_DRAIN_GRACE_MS 0 在 runner 收到关闭信号或到达其退役时间之前，控制 runner 在其活动会话结束后何时退出：0 表示立即退出而不再轮询更多工作；正值则使 runner 保持存活，并先在该秒数内重新轮询已锁定所有者的队列，代价是失去加固部分中所述的每会话容器隔离。如果您使用 --defer-shutdown-max-min 推迟了第一个信号，则无论此处如何设置，runner 都会在不再持有任何会话时立即退出。
                    --drain-marker-file <path> SELF_HOSTED_RUNNER_DRAIN_MARKER_FILE 未设置 标记文件，由您的主机在发送 SIGTERM 之前写入，以通告一次正常排空。如果排空开始时该文件存在，runner 会向 Anthropic 报告其退出原因为主机排空，而不是普通的关闭信号。排空过程本身（包括 --drain-wait-sec 的等待）与不使用该标志时相同。请指定本地文件系统上会话无法写入的路径。需要 Claude Code v2.1.271 或更高版本。
                    --drain-wait-sec <n> SELF_HOSTED_RUNNER_DRAIN_WAIT_MS 0 排空开始后（除非您设置了 --defer-shutdown-max-min，否则排空在收到 SIGTERM 时开始），最多等待 N 秒，让每个会话正在进行的轮次和后台任务完成，然后再终止子进程。在此等待期间，runner 会将刚刚完成的后台任务视为仍在运行，直到读取其结果的后续轮次开始为止，最长不超过 SELF_HOSTED_RUNNER_BG_RESULT_GRACE_MS 窗口。同时调高您的停止超时时间。
                    --environment-secret-file <path> SELF_HOSTED_RUNNER_ENVIRONMENT_SECRET 必需 包含环境密钥的文件路径；对于由编排器生成的 runner，则为一次性工作单 JWT 的文件路径。SELF_HOSTED_RUNNER_ENVIRONMENT_SECRET 直接携带密钥值，而不是文件路径。旧的 --pool-secret-file 标志和 SELF_HOSTED_RUNNER_POOL_SECRET 变量仍然有效，并会向 stderr 打印弃用通知；早于 2.1.216 的预览计划 runner 构建版本只识别这些旧名称。
                    --exec-path <path> SELF_HOSTED_RUNNER_EXEC_PATH 自身二进制文件 为每个会话生成的二进制文件或包装脚本。请参阅包装脚本。
                    --exit-if-unused-min <n> SELF_HOSTED_RUNNER_IDLE_SHUTDOWN_MS 0 在轮询 N 分钟且从未分配到任何工作后退出，用于自动扩缩器缩容。0 表示禁用。
                    --git-host-rewrite <from>=<to> 无 未设置 在克隆之前将 https://<from>/... 源 URL 改写为 https://<to>/...，用于拆分视图 DNS。可重复使用；仅限标志。
                    --git-ssh-rewrite <host> 无 未设置 在克隆之前将 https://<host>/... 源 URL 改写为 git@<host>:...，用于仅支持 SSH 的 git 主机。可重复使用；仅限标志。
                    --health-port <port> SELF_HOSTED_RUNNER_HEALTH_PORT 8080 /healthz 和 /metrics 监听器的端口。设置为 0 可禁用。
                    --hold-idle-file <path> SELF_HOSTED_RUNNER_HOLD_IDLE_FILE 未设置 由您的主机持续更改的文件，用于在 runner 上保留空闲会话。请参阅在进程运行期间保留空闲会话。需要 Claude Code v2.1.311 或更高版本。
                    --hooks-dir <path> SELF_HOSTED_RUNNER_HOOKS_DIR 未设置 生命周期 hook 脚本所在的目录。请参阅生命周期 hook。
                    --host-config-snapshot <mode> SELF_HOSTED_RUNNER_HOST_CONFIG_SNAPSHOT disk runner 保存主机配置目录启动快照的位置，runner 以该快照为每个会话提供初始内容。disk 会将快照复制到 --base-dir 下由 runner 拥有的目录中，并在每次会话启动时根据内存中的摘要校验每个文件。如果副本中的某个文件已被修改，该会话会失败，并且 runner 会拒绝会话，直到您重启它。memory 将整个快照保存在堆上，上限为 64 MiB；超过上限时，会话将在没有主机配置的情况下启动，并显示相应通知。当 runner 无法写入磁盘快照时，它会记录该失败，并在本次运行中使用 memory。需要 Claude Code v2.1.271 或更高版本。
                    --kill-session-after-min <n> SELF_HOSTED_RUNNER_MAX_LIFETIME_MS 0 将会话的挂钟时间限制为 N 分钟，作为针对卡住会话的安全限制。在 v2.1.260 或更高版本中，runner 会释放达到该限制的会话，以便其在用户发送下一条消息时恢复；只有当 SELF_HOSTED_RUNNER_MAX_LIFETIME_GRACE_MS 宽限窗口结束时该会话仍在 runner 上，才会将其终止。在 v2.1.260 之前，runner 会在达到限制时终止会话。有关详细信息以及如何选择取值，请参阅某些会话不计为空闲。0 表示禁用。
                    --lock-to-account <id> SELF_HOSTED_RUNNER_LOCK_TO_ACCOUNT 未设置 在启动时将 runner 预先锁定到特定账户，而不是在第一个会话时锁定。接受该环境所属组织中的电子邮件地址或 user_... ID。预先锁定的 runner 永远不会接收 Claude Tag 频道会话，因为这些会话没有账户。

                    • 标志：启动失败并报错。

                    会话启动超时

                    如果会话在 /code-review 等轮次中丢失了槽位，请将 runner 和子进程二进制文件更新到 v2.1.309 或更高版本。在 v2.1.299 至 v2.1.308 中，一旦启动超时已过且没有 user 或 assistant 消息，runner 就会释放会话，即使该会话正处于轮次中。

                    使用 --startup-timeout-min <n> 时，如果会话的子进程在克隆后 <n> 分钟内未完成初始化，runner 会释放该会话的槽位。在子进程初始化之前开始的轮次中，会话会保留其槽位，直到子进程的活动通道上连续 <n> 分钟没有任何输出行为止。子进程初始化后，runner 会清除该计时，改由 --release-idle-session-min 控制释放。要限制子进程仍存活但已卡住的会话，请设置 --kill-session-after-min。

                    自动模式规则列表

                    --server-auto-mode-lists 让您决定来自 runner 外部的哪些自动模式分类器规则可以作用于您的 runner 上的会话。Anthropic 的控制平面可以随会话发送规则列表，并请求 runner 应用它们。其中一些条目可能是您组织的管理员编写的规则。这些列表是 environment、soft_deny 和 allow：

                    • environment：其中的条目既可以让分类器允许更多操作，也可以让其允许更少操作。
                    • soft_deny：其中的条目会阻止某项操作，除非用户明确要求执行该操作，或适用某个 allow 例外。
                    • allow：soft_deny 条目的例外。

                    该标志的值决定 runner 应用哪些列表：

                    • no-allow：默认值。应用 environment 和 soft_deny，不应用 allow。environment 条目仍可能让分类器允许更多操作，因此默认值并不能排除所有放宽。
                    • all：应用全部三个列表。
                    • none：一个都不应用。若要排除来自这些列表的所有放宽，请选择 none。这也会去掉 soft_deny 的限制。

                    没有任何 runner 设置能让控制平面请求 runner 应用这些列表。当控制平面未发出请求时，无论您如何设置，会话都不会收到任何列表。要查看实际情况，请使用 --log-level debug 启动 runner。随后，runner 会为每个会话记录一行日志，其中包含 the server asked this runner to apply，或包含 the server did not ask this runner to apply the auto mode lists it sends。

                    遥测

                    会话子进程向 Anthropic 发送操作遥测，除非您关闭它。不发送代码或存储库内容。在运行器进程上设置遥测变量；运行器在应用服务器提供的环境变量后重新声明它们，因此操作员的设置始终优先。

                    一个控制特定于自托管环境：CLAUDE_CODE_BYOC_ENABLE_DATADOG=1 选择加入 Datadog 操作指标，这在自托管环境中默认关闭。一般 Claude Code 遥测控制 DISABLE_TELEMETRY、DO_NOT_TRACK、DISABLE_ERROR_REPORTING 和 CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC 适用于会话子进程，如环境变量参考中所述。DISABLE_GROWTHBOOK 相关但不同：设置 DISABLE_GROWTHBOOK=1 禁用功能标志获取，遥测保持开启，除非也设置了 DISABLE_TELEMETRY。

                    CLAUDE_CODE_ENABLE_TELEMETRY 无关：它启用 OpenTelemetry 导出到您自己的收集器，如监控中所述，不控制 Anthropic 的分析。

                    健康端点

                    运行器在配置的健康端口上提供 GET /healthz。只要进程活跃，响应就是 200 OK，无论轮询循环处于什么状态，因此此端点上的 HTTP 探针仅检测死进程。JSON 正文描述当前状态：

                    json
                    {
  "status": "ok",
  "runner_id": "ccrunner_...",
  "active_sessions": 2,
  "last_poll_at": "2026-03-31T18:04:11.220Z",
  "last_poll_age_ms": 842
}

                    在自定义探针中使用 last_poll_age_ms 作为活跃信号；无限增长的值表示轮询循环卡住。last_poll_at 和 last_poll_age_ms 都是 null，直到第一次轮询完成。

                    编排器自己的 /healthz（位于其健康端口上）始终返回 200。正文携带报告最近一次轮询是否成功的 connected 字段，加上 queue_counts 中的每个状态生成队列计数。要了解 connected 为何是 false，请读取顶层 last_error 字段，每次成功轮询都会将其重置为 null。使用 connected 而不是状态代码来控制就绪和警报。

                    当SCM 连接器被配置时，编排器的 /healthz 正文也携带 scm_connector_connected 和一个 scm_connector 对象，包含 connected、last_connected_at、last_error、reconnects 和 requests_forwarded。当未设置 --scm-connector-host 时，两个字段都是 null。

                    claude_code_self_hosted_runner_sessions_completed_total{client_platform} 干净结束的会话，标签方式相同。比普通干净退出更广泛：请参阅会话生命周期计数器语义了解计数内容。
                    claude_code_self_hosted_runner_sessions_failed_total{client_platform} 以失败结束的会话，标签方式相同。相同的注意事项：请参阅会话生命周期计数器语义。
                    claude_code_self_hosted_runner_sessions_interrupted_total{client_platform} 运行器因操作原因而不是会话结果终止的会话，标签方式相同。请参阅会话生命周期计数器语义。
                    claude_code_self_hosted_runner_initializing_sessions 当前处于初始化阶段的会话，从分配到子进程的初始化事件
                    claude_code_self_hosted_runner_session_init_duration_seconds 会话初始化持续时间的直方图
                    claude_code_self_hosted_runner_session_init_errors_total 在达到初始化前失败的会话：checkout 钩子失败、git 准备、令牌问题或初始化前子进程崩溃
                    claude_code_self_hosted_runner_session_start_hook_errors_total 报告错误结果的 SessionStart 钩子，每个失败的钩子执行一个
                    claude_code_self_hosted_runner_session_idle_seconds{session_id,client_platform} 每个会话的仪表，显示会话空闲以来的秒数。对于终止卡在未回答权限提示上的会话很有用。

                    针对丢失的运行器和等待中的会话发出警报

                    要在运行器丢失、会话等待或编排器停机时收到警报，请在示例警报规则之外加载以下 Prometheus 警报规则：

                    固定舰队丢失运行器时发出警报

                    当剩余的已注册且已被抓取的运行器数量低于下限并持续 10 分钟时，ClaudeRunnersBelowFloor 会触发：

                    yaml

  # 因此 ClaudeRunnersBelowFloor 会在需求较低时触发。
  - name: claude-code-self-hosted-fixed-fleet-capacity
    rules:
      - alert: ClaudeRunnersBelowFloor
        expr: (count(claude_code_self_hosted_runner_info{namespace="claude-runners"}) or vector(0)) < 2
        for: 10m
        labels: {severity: critical, namespace: claude-runners}
        annotations:
          summary: "已注册并被抓取的运行器：{{ $value }}，低于下限。请先检查运行器工作负载，如果全部在运行，再检查抓取目标。"

                    当等待运行器的会话数持续 10 分钟高于 0 时，ClaudeOrchestratorSessionsWaiting 会触发。当过去 10 分钟内超过 1% 的队列等待超过 160 秒，且该情况持续 5 分钟时，ClaudeOrchestratorQueueWaitHigh 会触发：

                    groups:
  # 仅适用于按需运行器。无需针对命名空间进行编辑。
  - name: claude-code-self-hosted-on-demand-capacity
    rules:
      - alert: ClaudeOrchestratorSessionsWaiting
        expr: |
          max by (namespace) (
            claude_code_self_hosted_orchestrator_pool_pending_sessions
            and on (instance)
            max_over_time(claude_code_self_hosted_orchestrator_connected[2m]) == 1
          ) > 0

        annotations:
          summary: "等待运行器的会话：{{ $value }}，已连续 10 分钟高于阈值。请按 result 检查 claude_code_self_hosted_orchestrator_spawn_hooks_total，然后检查未能启动的运行器工作负载。"
      - alert: ClaudeOrchestratorQueueWaitHigh
        expr: |
          histogram_quantile(0.99, sum by (namespace, le) (
            rate(claude_code_self_hosted_orchestrator_session_queue_wait_seconds_bucket[10m])

          summary: "过去 10 分钟内超过 1% 的队列等待超过 160 秒。请检查 ClaudeOrchestratorDisconnected 是否正在触发，然后按 result 检查 claude_code_self_hosted_orchestrator_spawn_hooks_total 以及 claude_code_self_hosted_orchestrator_spawn_hook_duration_seconds。"

                    • ClaudeOrchestratorDisconnected：保持从示例警报规则中加载它，因为在命名空间中最后一个编排器断开连接约 2 分钟后，ClaudeOrchestratorSessionsWaiting 会停止触发

                    yaml
                    groups:

  - name: claude-code-self-hosted-on-demand-orchestrator

      - alert: ClaudeOrchestratorAbsent
        expr: absent(claude_code_self_hosted_orchestrator_connected{namespace="claude-runners"})

          summary: "已有 5 分钟没有抓取到任何编排器。如果它已停机，则不会启动任何按需运行器，会话将处于等待状态。请先检查编排器工作负载，如果它在运行，再检查其抓取目标。"

                    传递会话子进程指标

                    每个会话在其自己的子进程中运行，具有自己的 OpenTelemetry 指标；在 --capacity 高于 1 时，运行器重写这些子指标的公开方式。在运行器主机上设置 OTEL_METRICS_EXPORTER=prometheus 和会话环境中的 CLAUDE_CODE_ENABLE_TELEMETRY=1（例如从您的包装脚本或运行器自己的环境，会话继承），重新公开每个子进程的计数器和仪表工具在运行器自己的 /metrics 端点上，与运行器的系列一起。运行器将子进程的导出器重写为通过 OTLP 推送到健康端口上的仅环回接收器，用 session_id 和 client_platform 标签标记每个系列，并在该会话结束时驱逐会话的系列。直方图不通过，子指标名称与运行器自己的前缀冲突的会被删除。

                    在默认 --capacity 1 处，重写不适用：会话的子进程照常在端口 9464 上绑定自己的 Prometheus 端点。

                    将会话的指标与运行器的指标关联

                    要查看空闲会话产生了多少成本，请基于 ccr_session_id 将运行器的 claude_code_self_hosted_runner_session_idle_seconds 与 Claude Code 的成本指标关联。运行器的指标不携带该标签，因此请使用 label_replace 为其添加一个，如以下查询所示：

                    text
                    sum by (ccr_session_id) (claude_code_cost_usage_total)
and on (ccr_session_id)
label_replace(
  claude_code_self_hosted_runner_session_idle_seconds > 600,
  "ccr_session_id", "cse_$1", "session_id", "session_(.*)"
)

                    该查询为每个空闲超过十分钟的会话返回一个结果：即其 Claude Code 进程迄今为止统计的以美元计的成本。要关联其他 Claude Code 指标，请替换查询中的 claude_code_cost_usage_total。该查询在任何 --capacity 下都有效。

                    • session_id：在端口 9464 上，Claude Code 指标上的该标签保存的是 Claude Code 自己的 session.id，它不与任何运行器系列匹配。基于它进行关联不会返回任何结果，因此请基于 ccr_session_id 进行关联。
                    • Claude Code 指标没有 ccr_session_id：请检查 OTEL_METRICS_INCLUDE_SESSION_ID 是否被设置为 false

                    会话生命周期计数器语义

                    sessions_started_total、sessions_completed_total、sessions_failed_total 和 sessions_interrupted_total 计数器按会话如何结束对其进行分类。每个生成的会话子进程在生成时增加 sessions_started_total，并且在退出时恰好增加其他三个中的一个，因此 sessions_started_total 减去其他三个的总和等于当前运行的会话子进程数。

                    • completed：会话干净结束。这涵盖子进程以代码 0 自行退出、会话在子进程仍连接时被存档或删除，以及运行器干净地交还槽：在空闲超时、退休时间或 --kill-session-after-min 限制处释放会话；启动超时；或轮询循环在子进程退出前注意到的服务器端取消分配。增加 sessions_completed_total。
                    • failed：子进程以非零代码自行退出，要么是崩溃，要么是生成后的设置失败。增加 sessions_failed_total。
                    • interrupted：运行器因既不是会话成功也不是运行器故障的操作原因终止子进程，例如排空，或终止在 SELF_HOSTED_RUNNER_MAX_LIFETIME_GRACE_MS 宽限期结束时仍在运行器上的会话，在其 --kill-session-after-min 限制之后。Kubernetes 滚动重启发送 SIGTERM 是排空的一个示例。增加 sessions_interrupted_total。

                    在 v2.1.260 之前，运行器终止达到其 --kill-session-after-min 限制的每个会话，并在 sessions_interrupted_total 中计数。

                    post-session 钩子的 CLAUDE_RUNNER_EXIT_REASON 以不同方式分类干净交接。钩子将以下情况报告为 interrupted，因为运行器停止了子进程：释放、启动超时、服务器取消分配，以及轮询先注意到的存档或删除。这些计数器记录与 completed 相同的事件，因为槽被干净地交还。

                    如果您直接根据 sessions_completed_total 协调钩子收据，您会低估完成。对每个会话保证使用钩子，对聚合速率使用计数器。

                    在一次性环境中，--capacity 1 与默认 --drain-grace-sec 0，每个运行器进程在其一个会话结束后片刻退出。sessions_completed_total、sessions_failed_total 和 sessions_interrupted_total 仅在会话结束时增加，在该退出之前，因此每 15 到 60 秒轮询一次 Prometheus 很少在运行器的系列消失前捕获增加；这三个会话结束计数器是本节其余部分所指的终端计数器。sessions_started_total 在生成时增加并在会话的生命周期内保持可见，因此它可靠地显示，但在一次性环境中它读取更接近"当前运行的会话"而不是累积计数。
