                    Agent SDK / 使用工具扩展

                    使用 MCP 连接外部工具

                    配置 MCP 服务器以扩展您的代理的外部工具。涵盖传输类型、大型工具集的工具搜索、身份验证和错误处理。

                    Model Context Protocol (MCP) 是一个开放标准，用于将 AI 代理连接到外部工具和数据源。使用 MCP，您的代理可以查询数据库、与 Slack 和 GitHub 等 API 集成，以及连接到其他服务，而无需编写自定义工具实现。

                    MCP 服务器可以作为本地进程运行、通过 HTTP 连接或直接在您的 SDK 应用程序中执行。

                    说明

                    本页面涵盖 Agent SDK 的 MCP 配置。要将 MCP 服务器添加到 Claude Code CLI 以便在每个项目中加载，请参阅 MCP 安装范围。

                    快速开始

                    此示例使用 HTTP 传输 连接到 Claude Code 文档 MCP 服务器，并使用 allowedTools 与通配符来允许来自服务器的所有工具。

                    typescript
                    import { query } from "@anthropic-ai/claude-agent-sdk";

for await (const message of query({
  prompt: "Use the docs MCP server to explain what hooks are in Claude Code",
  options: {
    mcpServers: {
      "claude-code-docs": {
        type: "http",
        url: "https://code.claude.com/docs/mcp"
      }
    },
    allowedTools: ["mcp__claude-code-docs__*"]
  }
})) {
  if (message.type === "result" && message.subtype === "success") {
    console.log(message.result);
  }
}
                    python
                    import asyncio
from claude_agent_sdk import query, ClaudeAgentOptions, ResultMessage


async def main():
    options = ClaudeAgentOptions(
        mcp_servers={
            "claude-code-docs": {
                "type": "http",
                "url": "https://code.claude.com/docs/mcp",
            }
        },
        allowed_tools=["mcp__claude-code-docs__*"],
    )

    async for message in query(
        prompt="Use the docs MCP server to explain what hooks are in Claude Code",
        options=options,
    ):
        if isinstance(message, ResultMessage) and message.subtype == "success":
            print(message.result)


asyncio.run(main())

                    代理连接到文档服务器，搜索有关 hooks 的信息，并返回结果。

                    添加 MCP 服务器

                    您可以在调用 query() 时在代码中配置 MCP 服务器，或在通过 settingSources 加载的 .mcp.json 文件中配置。

                    在代码中添加服务器

                    在 mcpServers 选项中直接传递 MCP 服务器。此示例为 /Users/me/projects 启动本地文件系统 MCP 服务器。将该路径替换为您机器上的目录：

                    typescript
                    import { query } from "@anthropic-ai/claude-agent-sdk";

for await (const message of query({
  prompt: "List files in my project",
  options: {
    mcpServers: {
      filesystem: {
        command: "npx",
        args: ["-y", "@modelcontextprotocol/server-filesystem", "/Users/me/projects"]
      }
    },
    allowedTools: ["mcp__filesystem__*"]
  }
})) {
  if (message.type === "result" && message.subtype === "success") {
    console.log(message.result);
  }
}
                    python
                    import asyncio
from claude_agent_sdk import query, ClaudeAgentOptions, ResultMessage


async def main():
    options = ClaudeAgentOptions(
        mcp_servers={
            "filesystem": {
                "command": "npx",
                "args": [
                    "-y",
                    "@modelcontextprotocol/server-filesystem",
                    "/Users/me/projects",
                ],
            }
        },
        allowed_tools=["mcp__filesystem__*"],
    )

    async for message in query(prompt="List files in my project", options=options):
        if isinstance(message, ResultMessage) and message.subtype == "success":
            print(message.result)


asyncio.run(main())

                    从配置文件添加服务器

                    在您的项目根目录创建一个 .mcp.json 文件。当启用 project 设置源时，该文件会被加载，默认 query() 选项已启用此功能。如果您显式设置 settingSources，请包含 "project" 以加载此文件。将 /Users/me/projects 替换为您机器上的目录：

                    json
                    {
  "mcpServers": {
    "filesystem": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem", "/Users/me/projects"]
    }
  }
}

                    连接时序

                    Claude Code 在会话启动时开始连接您的 MCP 服务器，并在第一轮等待（如果有的话）结束后发送 init 消息。第一轮等待某个服务器的时长取决于您在何处配置它。如果您设置了 permissionPromptToolName，无论您在何处配置该工具的服务器，第一轮始终会等待该服务器，最多等待 MCP_TIMEOUT。

                    对于 options.mcpServers 中的服务器，请在第一列中找到其类型，以查看第一轮等待它的时长。

                    服务器类型 延迟第一轮？ 第一轮等待超时
                    stdio 服务器，或没有缓存工具列表的 HTTP/SSE 服务器 是，直到连接 MCP_TIMEOUT，默认 30 秒；连接在该截止时间失败
                    具有缓存工具列表的远程服务器，由 Claude Code 从之前的连接保存 否；缓存的工具从第一轮开始可用 无；在其第一次工具调用时连接，该延迟连接有其自己的超时
                    进程内 SDK 服务器 是，直到连接并列出其工具 MCP_TIMEOUT，默认 30 秒，每次连接尝试；连接在该截止时间失败

                    只有在启用 MCP 发现缓存时，服务器才会有缓存的工具列表。

                    来自 设置文件（如 .mcp.json）或插件的服务器通常在 init 消息中仍显示 pending。第一轮等待它们的时长取决于 options.mcpServers 和 tool search：

                    • options.mcpServers 包含 stdio、HTTP 或 SSE 服务器：第一轮也会等待待处理的设置文件服务器和插件服务器，最多等待 MCP_TIMEOUT。
                    • 否则，当 ANTHROPIC_BASE_URL 指向网关且未设置 ENABLE_TOOL_SEARCH 时：第一轮最多等待 2 秒，等待每个待处理的设置文件服务器和插件服务器。
                    • 否则，在启用 tool search（默认启用）时：第一轮最多等待 2 秒，且仅等待设置了 alwaysLoad: true 或您已指名的待处理服务器。其余服务器继续在后台连接，Claude 会在它们连接后访问其工具。
                    • 否则，在关闭 tool search 时：第一轮最多等待 2 秒，等待每个待处理的设置文件服务器和插件服务器。当您的 ENABLE_TOOL_SEARCH 值或模型将其关闭，或当您排除 ToolSearch 工具（例如通过 disallowedTools）时，tool search 处于关闭状态。

                    指名服务器

                    您可以通过在 allowedTools 中或在 settings 选项的 permissions.allow 规则中列出服务器的任意工具（例如 mcp__github__list_issues 或 mcp__github__*）来指名该服务器。当您在提示提交、工具使用、权限、子代理、任务、elicitation 或 worktree 事件上配置 mcp_tool hook 时，它也会指名其调用的服务器。在 v2.1.284 之前，指名服务器不会影响第一轮等待。

                    自行设置第一轮等待

                    要自行选择第一轮等待时长，请在 env 选项中设置 CLAUDE_CODE_MCP_STARTUP_WAIT_MS，例如 CLAUDE_CODE_MCP_STARTUP_WAIT_MS: "5000"。此后第一轮会最多等待该毫秒数，以等待待处理的设置文件服务器和插件服务器，无论 tool search 是否启用。同一上限也会替代 options.mcpServers 中 stdio、HTTP 和 SSE 服务器的 MCP_TIMEOUT 等待。

                    无论您设置什么值（包括 0），以下三种等待都适用：

                    • permissionPromptToolName 服务器：最多等待 MCP_TIMEOUT。
                    • 进程内 SDK 服务器：每次连接尝试最多等待 MCP_TIMEOUT。
                    • 仍在连接中的指名服务器：等待上限至少为 2 秒，因此低于 2000 的值不会缩短其等待时间。

                    将该变量设置为 0 可跳过对其他所有服务器的等待。等待结束时仍处于待处理状态的服务器会继续在后台连接。CLAUDE_CODE_MCP_STARTUP_WAIT_MS 需要 Claude Code v2.1.274 或更高版本。

                    让启动等待服务器

                    有两项设置会让启动本身在 Claude Code 发送 init 消息之前进行等待：

                    • 将 MCP_CONNECTION_NONBLOCKING 设置为 0：启动会等待整个连接批次，默认最多 5 秒。设置 MCP_CONNECT_TIMEOUT_MS（单位为毫秒）可更改该上限。达到上限时仍处于待处理状态的服务器会继续在后台连接。
                    • 在服务器的配置上设置 alwaysLoad: true：启动会在相同上限内等待该服务器的工具，使第一轮能以完整 schema 获得这些工具，豁免于 tool search 延迟加载。具有缓存工具列表的远程服务器无需连接或阻塞启动即可提供这些工具。

                    init 消息报告的是 Claude Code 发送该消息时每个服务器的状态。

                    允许 MCP 工具

                    MCP 工具需要明确的权限才能让 Claude 使用它们。没有权限的情况下，Claude 会看到工具可用，但无法调用它们。

                    工具命名约定

                    MCP 工具的命名格式为 mcp__<server-name>__<tool-name>，其中 <server-name> 是您注册服务器时使用的名称，例如它在 mcpServers 中的键。

                    服务器名称中的 . 和空格等字符会被替换为 _。下表显示了两个服务器键下 list_issues 工具的完整名称：

                    mcpServers 中的键 完整工具名称
                    github mcp__github__list_issues
                    my.server mcp__my_server__list_issues

                    在 allowedTools 和 MCP 权限规则中使用完整的工具名称。对于由插件提供的服务器，<server-name> 采用插件作用域形式，并以 plugin_ 开头。

                    使用 allowedTools 自动批准

                    使用 allowedTools 自动批准特定的 MCP 工具，这样 Claude 就可以在没有权限提示的情况下使用它们：

                    typescript
                    const _ = {
  options: {
    mcpServers: {
      // your servers
    },
    allowedTools: [
      "mcp__github__*", // All tools from the github server
      "mcp__db__query", // Only the query tool from db server
      "mcp__slack__send_message" // Only send_message from slack server
    ]
  }
};
                    python
                    options = ClaudeAgentOptions(
    mcp_servers={
        # your servers
    },
    allowed_tools=[
        "mcp__github__*",  # All tools from the github server
        "mcp__db__query",  # Only the query tool from db server
        "mcp__slack__send_message",  # Only send_message from slack server
    ],
)

                    通配符（*）让你可以允许来自一个服务器的所有工具，而无需逐个列出。

                    说明

                    对于 MCP 访问，优先使用 allowedTools 而不是权限模式。 permissionMode: "acceptEdits" 不会自动批准 MCP 工具（仅限文件编辑和文件系统 Bash 命令）。permissionMode: "bypassPermissions" 会自动批准 MCP 工具，但也会禁用大多数其他安全提示，这比必要的范围更广；请参阅 权限如何被评估 了解保留的提示。allowedTools 中的通配符仅授予你想要的 MCP 服务器，不会授予其他任何东西。请参阅 权限模式 了解完整的比较。

                    发现可用工具

                    要查看 MCP 服务器提供的工具，请检查服务器的文档或检查 system init 消息中的 tools 数组。MCP 工具名称以 mcp__ 开头。

                    Claude Code 在 首次连接等待 之后为在 options.mcpServers 中传递的服务器发出 init 消息，因此 tools 数组列出了到那时已连接的每个服务器的 mcp__ 工具，以及具有 缓存工具列表 的服务器的工具，这些服务器在首次使用时连接。任何其他尚未连接的服务器的工具不存在；请参阅 错误处理 了解如何读取每个服务器的状态。

                    OAuth2 身份验证

                    MCP 规范支持 OAuth 2.1 用于授权。SDK 不会打开浏览器或运行交互式 OAuth 流程。当配置的服务器返回授权质询而 Claude Code 没有可发送的令牌时，SDK 会将该服务器报告为 needs-auth 或 failed：

                    • needs-auth：Claude Code 未找到可用于该服务器的登录信息。请在 headers 中传递令牌，或在运行之前在同一台机器上从交互式 Claude Code 会话中登录。
                    • failed，且其 McpServerStatus 条目中的 error 以 Couldn't read the stored credentials 或 A request to MCP server 开头：Claude Code 无法读取其凭据存储。有关处理方法，请参阅 Couldn't read the stored credentials for MCP server。在 Claude Code v2.1.307 之前，当 Mac 的登录钥匙串被锁定时，状态会显示为 needs-auth。

                    无论哪种情况，Agent 运行都会继续，但不使用该服务器的工具。系统初始化消息的 mcp_servers 数组在发出时可能仍会为该服务器显示 pending。要确认服务器是否需要凭据，请在 TypeScript SDK 中轮询 mcpServerStatus() 或在 Python 中轮询 get_mcp_status()。

                    错误处理

                    MCP 服务器可能因各种原因连接失败：服务器进程可能未安装、凭证可能无效，或远程服务器可能无法访问。

                    Claude Code 在每个查询开始时发出一条 system 类型、子类型为 init 的消息。此消息包括每个 MCP 服务器的连接状态。status 字段可以是 "pending"、"connected"、"failed"、"needs-auth" 或 "disabled"。Claude Code 在 首次转换连接等待 之后为在 options.mcpServers 中传递的服务器发出 init 消息，因此在等待时间内连接的服务器会显示 "connected"。

                    在 init 消息中，不要将 "pending" 本身视为失败。它可能意味着以下任何一种情况：

                    • 服务器尚未连接。请参阅 Claude Code 在首次转换前等待多长时间
                    • 服务器的工具列表是 从缓存提供的，连接在首次使用时建立
                    • 连接截止时间已过期。此类服务器根据时间报告 "pending" 或 "failed"

                    检查 "failed" 或 "needs-auth" 以检测无法使用的服务器：

                    typescript
                    import { query } from "@anthropic-ai/claude-agent-sdk";

try {
  for await (const message of query({
    prompt: "Process data",
    options: {
      mcpServers: {
        // Replace dataServer with your server configuration
        "data-processor": dataServer
      }
    }
  })) {
    if (message.type === "system" && message.subtype === "init") {
      const unavailableServers = message.mcp_servers.filter(
        (s) => s.status === "failed" || s.status === "needs-auth"
      );

      if (unavailableServers.length > 0) {
        console.warn("Unavailable MCP servers:", unavailableServers);
      }
    }

    if (message.type === "result" && message.subtype === "error_during_execution") {
      console.error("Execution failed");
    }
  }
} catch (error) {
  // A single-shot query() throws after yielding an error result. If the
  // failure was an error result, the error subtype branch above has
  // already run; a failure to start or reach the Claude Code process
  // yields no result message. MCP servers that fail to connect don't
  // throw: use the status check above, and note that servers still
  // "pending" at init need a later status check.
  console.log(`Session ended with an error: ${error}`);
}
                    python
                    import asyncio
from claude_agent_sdk import query, ClaudeAgentOptions, SystemMessage, ResultMessage

                    远程服务器的状态在报告 "connected" 后也可能会改变。当连接在会话中途断开时，Claude Code 会在 重新连接 时将服务器移回 "pending"。之后在 TypeScript 中调用 mcpServerStatus()，或在 Python 中调用 ClaudeSDKClient.get_mcp_status()，可能会为您之前看到已连接的服务器报告 "pending"，而您这一方没有进行任何配置更改。

                    在五次重新连接尝试失败后，服务器报告 "failed"，或在需要再次授权时报告 "needs-auth"。处于 "failed" 状态的 HTTP 或 SSE 服务器仍可能在您无需调用任何方法的情况下恢复为 "connected"，因为 Claude Code 在发生暂时性错误后会持续在后台重试。要手动重试，请在 TypeScript 中调用 reconnectMcpServer() 或在 Python 中调用 ClaudeSDKClient.reconnect_mcp_server()。

                    SDK MCP 服务器中缺少某个工具

                    在 TypeScript SDK 中，当某个工具的输入 schema 无法转换为 JSON Schema 时，您使用 createSdkMcpServer() 创建的服务器在列出其工具时会省略该工具。此时 SDK 会发出一条警告。在 Node.js 下，该警告是一个代码为 CLAUDE_SDK_MCP_TOOL_SCHEMA_UNCONVERTIBLE 的进程警告，并以以下文本开头：

                    text
                    Tool "<name>" on SDK MCP server "<server>" was left out of the server's tool list, because its input schema cannot be converted to JSON Schema

                    警告的其余部分会给出转换错误的消息（如果有），然后说明需要检查和更改的内容。

                    在 TypeScript Agent SDK v0.3.286 之前，只要有一个无法转换的 schema，就会导致该服务器的整个工具列表失败且不显示此警告，因此该服务器的所有工具都无法提供给 Claude。

                    连接超时

                    MCP 服务器连接默认在 30 秒后超时。要更改运行中的工具调用可能需要的时间，请设置 MCP_TOOL_TIMEOUT。如果您的服务器需要更长时间才能启动，连接将失败。使用 MCP_TIMEOUT 环境变量（以毫秒为单位）提高连接限制。对于需要更多启动时间的服务器，还应考虑：

                    • 使用更轻量级的服务器（如果可用）
                    • 在启动代理之前预热服务器
                    • 检查服务器日志以查找缓慢初始化的原因

                    在 TypeScript 中，您可以通过将 timeout 传递给 createSdkMcpServer() 来为单个 SDK MCP 服务器 设置工具调用限制。

                    工具输出超过最大允许令牌数

                    SDK 应用与 Claude Code 相同的 MCP 输出限制。当不含图像内容的成功工具结果大于 25,000 个 token 时，Claude Code 会将输出保存到文件中，并用一条指明文件路径的错误消息替换工具结果，以便 Agent 可以分部分读回输出。

                    要更改 token 限制，请设置 MAX_MCP_OUTPUT_TOKENS 环境变量。除非工具声明了 anthropic/maxResultSizeChars，否则长度超过 50,000 个字符的成功文本结果无论 token 限制如何都会被保存到文件中。请参阅 MCP 输出限制和警告 了解完整行为，包括服务器如何声明该注释。
