Cron 触发器

用一条 cron 表达式，让 Worker 按计划自动执行。

配置 原文更新于 2026-10-17 对应页面：configuration/cron-triggers

背景

Cron 触发器（Cron Triggers）让用户把一条 cron 表达式映射到 Worker 上——通过 scheduled() 处理器，Worker 就能按计划执行。

Cron 触发器非常适合跑周期性任务，例如日常维护，或定时调用第三方 API 拉取最新数据。被 Cron 触发器调度的 Worker 会跑在利用率较低的机器上，从而更好地利用 Cloudflare 的容量、并高效地调度流量。

注意

Cron 触发器也可以直接在 Workflows ↗ 中使用，方式是 Workflow 绑定上的 schedules。详见触发 Workflows ↗，并注意使用支持 Workflow 调度的 Wrangler 版本。

Cron 触发器按 UTC 时间执行。

添加 Cron 触发器

1. 定义 scheduled 事件监听器

要响应 Cron 触发器，必须给 Worker 加上 "scheduled" 处理器。

export default {
	async scheduled(controller, env, ctx) {
		console.log("cron processed");
	},
};
interface Env {}
export default {
	async scheduled(
		controller: ScheduledController,
		env: Env,
		ctx: ExecutionContext,
	) {
		console.log("cron processed");
	},
};
from workers import WorkerEntrypoint

class Default(WorkerEntrypoint):
    async def scheduled(self, controller, env, ctx):
        # All four parameters (self, controller, env, ctx) are required
        print("cron processed")

更多写法可参考这两个示例：设置 Cron 触发器、多个 Cron 触发器。

2. 更新配置

Cron 触发器改动的传播需要时间

新增、修改或删除 Cron 触发器，可能要几分钟（最长 15 分钟）才能传播到 Cloudflare 全球网络。

给 Worker 代码加上 "scheduled" 事件之后，还要更新项目配置。

通过 cloudflare.config.ts

用 Cloudflare CLI ↗ 管理的项目，在 cloudflare.config.ts 的 worker.triggers 里添加 triggers.scheduled() 条目：

原站此处是交互式 API 参考

原文这一节是一个可展开的类型提示组件，逐项说明 defineConfig、worker、name、entrypoint、compatibilityDate、triggers 与 triggers.scheduled({ schedule }) 的签名与含义。要点如下：

  • defineConfig(config)：定义 cloudflare.config.ts 的默认导出，可传配置对象、解析为该对象的 Promise，或接收配置上下文（isPreview、mode）并返回配置的函数。
  • worker.name（必填）：Worker 名称。
  • worker.entrypoint（可选）：入口模块，可以是路径字符串（如 "./src/index.ts"），也可以是带 cf-worker 导入属性的模块命名空间。
  • worker.compatibilityDate（必填）：yyyy-mm-dd 形式的日期，决定使用哪个 Workers 运行时版本。
  • worker.triggers（可选）：事件触发器数组，可用 triggers.fetch()、triggers.queue()、triggers.scheduled()、triggers.email()、triggers.connect() 构造。
  • triggers.scheduled({ schedule })：cron 定义，schedule 为必填字符串。
import { defineConfig, triggers } from "cf/config";
import * as entrypoint from "./src/index.ts" with { type: "cf-worker" };

export default defineConfig({
	worker: {
		name: "my-worker",
		entrypoint,
		compatibilityDate: "<COMPATIBILITY_DATE>",
		triggers: [triggers.scheduled({ schedule: "0 * * * *" })],
	},
});

本地测试处理器用 cf dev；部署配置好的调度用 cf deploy。

通过 Wrangler 配置文件

如果 Worker 由 Wrangler 管理，Cron 触发器应只通过 Wrangler 配置文件管理。

{
	"triggers": {
		// Schedule cron triggers:
		// - At every 3rd minute
		// - At 15:00 (UTC) on first day of the month
		// - At 23:59 (UTC) on the last weekday of the month
		"crons": [
			"*/3 * * * *",
			"0 15 1 * *",
			"59 23 LW * *"
		]
	}
}
[triggers]
crons = [ "*/3 * * * *", "0 15 1 * *", "59 23 LW * *" ]

你也可以为 Wrangler 配置文件中的每个环境设置不同的 Cron 触发器——把 triggers 数组放进对应环境里即可：

{
	"env": {
		"dev": {
			"triggers": {
				"crons": [
					"0 * * * *"
				]
			}
		}
	}
}
[env.dev.triggers]
crons = [ "0 * * * *" ]

通过控制台

  1. 在 Cloudflare 控制台进入 Workers & Pages。前往 Workers & Pages ↗
  2. 在 Overview 中选择你的 Worker > Settings > Triggers > Cron Triggers。

支持的 cron 表达式

Cloudflare 支持五字段的 cron 表达式，以及大部分 Quartz 调度器 ↗风格的语法扩展：

字段取值可用字符
分钟（Minute）0-59* , - /
小时（Hours）0-23* , - /
日（Days of Month）1-31* , - / L W
月（Months）1-12，以及不区分大小写的三字母缩写（"JAN"、"aug" 等）* , - /
星期（Weekdays）1-7，以及不区分大小写的三字母缩写（"MON"、"fri" 等）* , - / L #
注意

星期取值从 1＝周日 到 7＝周六，这与某些 cron 系统不同（那些系统里 0＝周日、6＝周六）。为避免歧义，建议直接用三字母缩写（例如用 SUN 而不是 1）。

示例

一些常用的时间间隔，便于设置 Cron 触发器：

  • * * * * * —— 每分钟
  • */30 * * * * —— 每 30 分钟
  • 45 * * * * —— 每小时的第 45 分钟
  • 0 17 * * sun 或 0 17 * * 1 —— 周日 17:00（UTC）
  • 10 7 * * mon-fri 或 10 7 * * 2-6 —— 工作日 07:10（UTC）
  • 0 15 1 * * —— 每月 1 日 15:00（UTC）
  • 0 18 * * 6L 或 0 18 * * friL —— 每月最后一个周五 18:00（UTC）
  • 59 23 LW * * —— 每月最后一个工作日 23:59（UTC）

本地测试 Cron 触发器

用 cf dev ↗、wrangler dev 或 Cloudflare Vite 插件在本地测试 Cron 触发器。可以用 Local Explorer，也可以直接发一个 HTTP 请求。

在 Local Explorer 中测试 Cron 触发器，需要 Wrangler 4.139.0 或更高版本，或 Cloudflare Vite 插件 1.60.0 或更高版本。由 cf dev 启动的开发服务器同样有这一要求。

使用 Local Explorer

Local Explorer 会显示当前环境实际配置的 Cron 触发器，也能在不改配置的前提下临时测试任意表达式。

要测试已配置的表达式，当前环境至少得有一个 Cron 触发器；而临时表达式不配置也能测。

  1. 打开 Local Explorer，选择要测试的 Worker。
  2. 选择 Cron Triggers > Configured Crons。
  3. 选择 Now，或添加一个预设的调度时间。
  4. 在要测试的表达式旁选择 Trigger。
  5. 查看处理器结果、noRetry() 状态、实际派发的表达式与调度时间。

完整的调用日志在拥有该 Worker 的开发会话里查看，且该会话必须开启 Observability。

每次调用都是一次性本地测试，本地开发不会自动运行 Cron 触发器。

要测试未配置的表达式，选择 Cron Triggers > Ad-Hoc Triggers。临时触发器只留在你的浏览器里，不会改动已部署的 Cron 触发器。

用 HTTP 请求测试

本地开发服务器暴露了两个用于触发 scheduled 调用的端点。下面的例子用的是 8787 端口；请以你的开发服务器实际打印的端口为准（用 cf dev 启动时也一样）。Vite 默认使用 5173 端口。

使用 scheduled 路由

向 /cdn-cgi/local/scheduled 发请求即可调用 scheduled 处理器。

curl "http://localhost:8787/cdn-cgi/local/scheduled"

默认以文本返回处理器结果。要拿到结构化的 JSON 结果，加上 ?format=json。

curl "http://localhost:8787/cdn-cgi/local/scheduled?format=json"
{
  "outcome": "ok",
  "noRetry": false
}

当 scheduled 处理器调用了 controller.noRetry() 时，noRetry 字段为 true。

还可以传 cron 查询参数，模拟不同的 cron 模式。

curl "http://localhost:8787/cdn-cgi/local/scheduled?cron=*+*+*+*+*"

也可以传 time 查询参数，用来覆盖 scheduled 事件监听器里的 controller.scheduledTime。

curl "http://localhost:8787/cdn-cgi/local/scheduled?cron=*+*+*+*+*&time=1745856238000"

使用 Local Explorer API

要精确指定 Local Explorer 可见的某个 Worker，向 /cdn-cgi/local/explorer/api/local/scheduled?worker=<WORKER_NAME> 发 POST 请求。worker 查询参数必须与 Worker 名称完全一致。可用 Worker 名列表可向 /cdn-cgi/local/explorer/api/local/workers 发 GET 获取。

JSON 请求体里 cron 字段必填且不能为空；可选的 scheduled_time 用毫秒时间戳设置 controller.scheduledTime，省略时默认取当前时间。

curl -X POST \
  "http://localhost:8787/cdn-cgi/local/explorer/api/local/scheduled?worker=my-worker" \
  -H "Content-Type: application/json" \
  --data '{"cron":"0 * * * *","scheduled_time":1745856238000}'

响应采用 Local Explorer API 的统一信封格式，其中 result 包含处理器的 outcome 与 noRetry 值。API 请求成功不等于处理器执行成功——请始终检查 result.outcome。

查看历史事件

要查看 Cron 触发器的执行历史，打开 Cron Events：

  1. 在 Cloudflare 控制台进入 Workers & Pages。前往 Workers & Pages ↗
  2. 在 Overview 中选择你的 Worker。
  3. 选择 Settings。
  4. 在 Trigger Events 下选择 View events。

Cron Events 保存最近 100 次 Cron 调度事件调用。Workers Logs 也会记录 Cron 触发器的调用日志，保留期更长，并提供过滤与查询界面。如果需要用 API 访问 Cron Events，可以使用 Cloudflare 的 GraphQL Analytics API ↗。

注意

新建 Worker 或修改 Worker 名称后，事件最长可能需要 30 分钟才会出现在 Past Cron Events 里。

更多信息见指标与分析。

删除 Cron 触发器

通过控制台

  1. 在 Cloudflare 控制台进入 Workers & Pages。前往 Workers & Pages ↗
  2. 选择你的 Worker。
  3. 进入 Triggers > 点要删除的 Cron 触发器旁的三点图标 > Delete。

通过 Wrangler 配置文件

如果 Worker 由 Wrangler 管理，Cron 触发器应只通过 Wrangler 配置文件管理。

用 Wrangler 部署时，之前的所有 Cron 触发器会被 triggers 数组中的内容替换：

  • crons 属性为空数组时，所有 Cron 触发器都会被删除。
  • triggers 或 crons 为 undefined 时，当前已部署的 Cron 触发器保持不变。
{
	"triggers": {
		// Remove all cron triggers:
		"crons": []
	}
}
[triggers]
crons = [ ]

限额

每个账户可创建的 Cron 触发器上限见 Workers 限额。

Green Compute

启用 Green Compute 后，你的 Cron 触发器只会在完全由可再生能源供电的数据中心里的 Cloudflare 节点上运行。如果一家机构采购的可再生能源足以覆盖其总体能耗，就可以宣称自己是 100% 可再生能源供电。

可再生能源有多种采购方式：现场发电（风力发电机、光伏板）、通过名为购电协议（PPA）的合同直接从可再生能源生产商购买，或从能源凭证市场购买可再生能源凭证（REC、IRECs、GoOs）。

Green Compute 可在账户级配置：

  1. 在 Cloudflare 控制台进入 Workers & Pages。前往 Workers & Pages ↗
  2. 在 Account details 区域找到 Compute Setting。
  3. 选择 Change。
  4. 选择 Green Compute。
  5. 选择 Confirm。
