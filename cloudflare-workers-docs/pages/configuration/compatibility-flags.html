兼容性标志

逐个开关运行时行为：用标志提前试用、或回退某个变更。

配置 原文更新于 2026-09-18 对应页面：configuration/compatibility-flags

兼容性标志（compatibility flags）用于启用特定特性。它有两种典型用途：帮 Workers 团队测试尚未默认启用的改动；或者你的代码依赖某个旧行为，需要留住它、同时又想应用其他兼容性变更。

兼容性标志通常会有一个「默认启用」的日期。因此只要给你的 Worker 指定 compatibility_date，就能一次性启用截至该日期（含该日期）的全部标志。

设置兼容性标志

你可以提供一个 compatibility_flags 列表，用来启用或禁用特定变更。

通过 Wrangler

兼容性标志可以在 Worker 的 Wrangler 配置文件中设置。

下例启用了 formdata_parser_supports_files 这个标志。在 2021-09-14 这个日期下它尚未默认启用，但写进 compatibility_flags 就能启用它。反过来，compatibility_flags 也可以用来关掉过去已变成默认的变更（在标志名前面加 no_）。

{
	// Opt into backwards-incompatible changes through September 14, 2021.
	"compatibility_date": "2021-09-14",
	// Also opt into an upcoming fix to the FormData API.
	"compatibility_flags": [
		"formdata_parser_supports_files"
	]
}
compatibility_date = "2021-09-14"
compatibility_flags = [ "formdata_parser_supports_files" ]

通过 Cloudflare 控制台

兼容性标志可以在 Cloudflare 控制台 ↗的 Workers 设置里更新。

通过 Cloudflare API

用 Workers Script API ↗ 或 Workers Versions API ↗ 上传 Worker 时，可以在请求体的 metadata 字段里设置兼容性标志。

Node.js 兼容性标志

注意

对于 2024-09-23 至 2026-08-03（含）之间的兼容性日期，nodejs_compat 标志会同时启用 nodejs_compat_v2。v2 会把更多 polyfill 与全局对象打包进 Worker，从而改善 Node.js 兼容性，代价是包体积变大。

兼容性日期在 2024-09-22 及之前时，需要在 nodejs_compat 之外再加 nodejs_compat_v2 才能开启 v2；在 2024-09-23 至 2026-08-03 之间，则加 no_nodejs_compat_v2 来只用 v1。

兼容性日期为 2026-08-04 及之后时，Workers 与 Pages 项目会默认同时启用 nodejs_compat 与 nodejs_compat_v2，无需任何配置；这些标志对该日期已无作用，新配置里可以省略，老项目更新日期时也不必删除。

Node.js 的 AsyncLocalStorage 对 Workers 特别有用。只想启用这一个 API 时，用 nodejs_als 标志。
