workers.dev 子域

免费赠送的测试用子域：快速上手够用，生产请换自定义域名。

配置 原文更新于 2026-09-22 对应页面：configuration/routing/workers-dev

Cloudflare Workers 账户自带一个 workers.dev 子域，可以在 Cloudflare 控制台里配置。有了它，你不必先把自定义域名接入 Cloudflare，就能立刻部署 Worker。

生产环境的 Worker 建议跑在 Workers 路由或自定义域名上，而不是 workers.dev 子域。你的 workers.dev 子域按 免费网站 ↗对待，定位于个人或兴趣项目，不适合承载关键业务。

配置 workers.dev

workers.dev 子域的格式是：<YOUR_ACCOUNT_SUBDOMAIN>.workers.dev。要修改你的子域：

  1. 在 Cloudflare 控制台进入 Workers & Pages。前往 Workers & Pages ↗
  2. 在 Your subdomain 旁选择 Change。

所有 Worker 在创建或重命名时都会被分配一条 workers.dev 路由，格式为 <YOUR_WORKER_NAME>.<YOUR_SUBDOMAIN>.workers.dev。Worker 配置里的 name 字段就用作已部署 Worker 的子域。

管理 workers.dev 的访问权限

启用后，你的 workers.dev URL 是公开可访问的。你可以用 Cloudflare Access ↗ 要求访问者在打开版本 URL、预览 URL与部署 URL 之前先完成认证。你可以在访问策略里把访问范围限定为自己、队友、组织，或你指定的任何人。

Access 可以保护某个 Worker 的生产 workers.dev URL、预览 URL，或两者都保护；也可以保护账户下所有 Worker 或所有 Worker 预览。

要在 Worker 里使用已登录用户的详细信息，请用 ctx.access。你也可以从校验过的 JWT 或 /cdn-cgi/access/get-identity 端点读取用户身份 ↗。

禁用 workers.dev

在控制台禁用

  1. 在 Cloudflare 控制台进入 Workers & Pages。前往 Workers & Pages ↗
  2. 在 Overview 中选择你的 Worker。
  3. 进入 Settings > Domains & Routes。
  4. 在 workers.dev 上点击 "Disable"。
  5. 确认禁用。

在 Wrangler 配置文件中禁用

在该 Worker 的 Wrangler 配置文件中写入：

{
	"workers_dev": false
}
workers_dev = false

带上这项改动重新部署后，workers.dev 路由即被禁用。注意：禁用该路由不会同时禁用版本 URL、预览 URL或部署 URL。

如果你没有写 workers_dev = false，而是给 Wrangler 配置文件加了 routes 段，那么下次部署时 workers_dev 会被推断为 false。

谨慎

如果你在 Cloudflare 控制台禁用了 workers.dev 路由，却没有把 Wrangler 文件里的 workers_dev 改成 false，那么下次用 Wrangler 部署时，这条路由会被重新启用。

限制

启用 workers.dev 子域部署 Worker 时，Worker 名称必须满足：

  • 不超过 63 个字符；
  • 只能包含字母数字（a-z、A-Z、0-9）与连字符（-）；
  • 不能以连字符开头或结尾。

之所以有这些限制，是因为 Worker 名称会被用作 workers.dev URL 中的 DNS 标签，而 DNS 标签最长 63 个字符，且不能以连字符开头或结尾。

注意

不使用 workers.dev 子域时，Worker 名称最长可达 255 个字符。如果你需要更长的名字，可以禁用 workers.dev，改用路由或自定义域名。
