自定义域名

把 Worker 接到域名或子域上，DNS 与证书都由 Cloudflare 代办。

配置 原文更新于 2026-09-29 对应页面：configuration/routing/custom-domains

背景

自定义域名（Custom Domains）让你把 Worker 接到域名或子域上，而不必改 DNS 设置、也不用自己管证书。为 Worker 设置好自定义域名后，Cloudflare 会代你创建 DNS 记录并签发所需证书，且这些记录直接指向该 Worker。与路由不同，自定义域名会把某个域名或子域的所有路径都指向 Worker。

自定义域名是 Cloudflare 区域内的路由：指向某个域名或子域（例如 example.com 或 shop.example.com），此时 Worker 就是源站。

如果你要把 Worker 接到互联网、并且没有需要始终与之通信的应用服务器，推荐用自定义域名。万一对接到外部依赖，可以构造一个带目标 URI 的 Request 对象，用 fetch() 去访问。

自定义域名可以层层叠加。比如 Worker A 挂在 app.example.com、Worker B 挂在 api.example.com，那么 Worker A 可以对 api.example.com 发起 fetch() 来调用 Worker B。

另外，与路由不同，自定义域名可以在同一区域内通过 fetch() 被调用。

添加自定义域名

要添加自定义域名，你需要：

  1. 一个处于活跃状态的 Cloudflare 区域 ↗；
  2. 一个可被调用的 Worker。

可以通过 Cloudflare 控制台、Wrangler 或 API ↗ 把自定义域名挂到 Worker 上。

谨慎

不能在已有 CNAME DNS 记录的主机名上创建自定义域名，也不能在你并不拥有的区域上创建。

在控制台设置自定义域名

  1. 在 Cloudflare 控制台进入 Workers & Pages。前往 Workers & Pages ↗
  2. 在 Overview 中选择你的 Worker。
  3. 进入 Settings > Domains & Routes > Add > Custom Domain。
  4. 填入要为该 Worker 配置的域名。
  5. 选择 Add Custom Domain。

添加完成后，Cloudflare 会为你创建新的 DNS 记录。自定义域名可以添加多个。

为自定义域名要求登录

要让访问者在打开自定义域名前先登录，请使用 Cloudflare Access。

你可以用基于主机名的 Access 保护某个自定义域名，也可以保护 Worker 本身——覆盖它的路由、自定义域名、workers.dev 主机名与预览。详见 Cloudflare Access。

在 Wrangler 配置文件中设置自定义域名

在 Wrangler 配置文件的 routes 里，给每个 pattern 加上 custom_domain=true：

{
	"routes": [
		{
			"pattern": "shop.example.com",
			"custom_domain": true
		}
	]
}
[[routes]]
pattern = "shop.example.com"
custom_domain = true

要配置多个自定义域名：

{
	"routes": [
		{
			"pattern": "shop.example.com",
			"custom_domain": true
		},
		{
			"pattern": "shop-two.example.com",
			"custom_domain": true
		}
	]
}
[[routes]]
pattern = "shop.example.com"
custom_domain = true

[[routes]]
pattern = "shop-two.example.com"
custom_domain = true

Worker 之间的通信

在同一区域内，如果目标 Worker 跑在路由上或 workers.dev 子域上，那么另一个 Worker 想跟它通信，唯一的方式是服务绑定。

而在同一区域内，如果目标 Worker 跑在自定义域名上而不是路由上，这个限制就解除了：同区内的 Worker 之间，向挂在自定义域名上的 Worker 发 fetch 请求可以直接成功，无需服务绑定。

举例：两个 Worker 都跑在 example.com 这一 Cloudflare 区域上。

  • worker-a 跑在路由 auth.example.com/* 上；
  • worker-b 跑在路由 shop.example.com/* 上。

此时 worker-a 向 worker-b 发 fetch 请求会失败，因为同区 fetch 请求有上述限制；worker-a 必须为 worker-b 配置服务绑定才能成功。

export default {
	fetch(request) {
		// This will fail
		return fetch("https://shop.example.com");
	},
};

但如果 worker-b 改成跑在自定义域名 shop.example.com 上，这个 fetch 请求就会成功。

请求匹配行为

自定义域名不支持通配符 DNS 记录 ↗。入站请求必须与自定义域名所注册的域名或子域完全一致；URL 的其他部分（路径、查询参数）不参与这套匹配逻辑。例如给 api-gateway 这个 Worker 在 api.example.com 上建了自定义域名，那么 api.example.com/login 与 api.example.com/user 的请求都会调用同一个 api-gateway。

与路由的相互配合

跑在自定义域名上的 Worker 被视作一个源站。位于该自定义域名之前的、跑在路由上的任何 Worker，都可以选择用入站的 Request 对象发起 fetch(request) 来调用它。这意味着你可以安排多个 Worker 在请求到达自定义域名 Worker 之前先运行——换句话说，可以在同一个请求里串起两个 Worker。

例如下面这个流程：

  1. api.example.com 的自定义域名指向 api-worker。
  2. 为 api.example.com/auth 添加的路由指向 auth-worker。
  3. 发往 api.example.com/auth 的请求会触发 auth-worker。
  4. 在 auth-worker 里用 fetch(request) 就会调用 api-worker，就像它是一台普通的应用服务器。
export default {
	fetch(request) {
		const url = new URL(request.url);
		if (url.searchParams.get("auth") !== "SECRET_TOKEN") {
			return new Response(null, { status: 401 });
		} else {
			// This will invoke `api-worker`
			return fetch(request);
		}
	},
};

证书

创建自定义域名还会在目标区域上为目标主机名签发一张 高级证书（Advanced Certificate）↗。

这包括 realms.app.example.com 这种多级子域。Universal SSL ↗ 只覆盖根域与一级子域，所以二级及更深的子域不在 Universal SSL 覆盖范围内——由自定义域名生成的证书来覆盖，而且不需要单独订阅 Advanced Certificate Manager。

这些证书以默认设置生成。要覆盖这些设置，可以删除生成的证书，在 Cloudflare 控制台里创建你自己的证书。操作步骤见管理高级证书 ↗。

谨慎

删除自定义域名时，关联的高级证书不会被自动删除。你需要在 Cloudflare 控制台的 SSL/TLS > Edge Certificates 下手动移除，或通过 API ↗ 删除。留着不用的证书不影响功能，但在审计证书清单时容易造成困惑。

在 www 与根域之间重定向

由于自定义域名要求主机名精确匹配，挂在 example.com 上的 Worker 收不到发往 www.example.com 的请求，反之亦然。要让两个版本都能用，请设置重定向规则：

  • 从 www 重定向到根域 ↗
  • 从根域重定向到 www ↗

同时还需要为被重定向的那个主机名配置一条经代理的 DNS 记录 ↗，Cloudflare 才能施加重定向规则。

  • www → 根域：为 www 添加指向 192.0.2.0 的代理 A 记录，或指向 100:: 的代理 AAAA 记录。
  • 根域 → www：为根域添加指向 192.0.2.0 的代理 A 记录，或指向 100:: 的代理 AAAA 记录。
注意

192.0.2.0（A 记录）与 100::（AAAA 记录）是无源站架构用的保留占位地址 ↗。由于该 DNS 记录经过代理，请求永远不会到达这个地址——Cloudflare 会拦截并施加你的重定向规则。

从路由迁移到自定义域名

如果你现在用带 /* 的路由调用 Worker，并且有一条指向 100:: 之类的 CNAME 记录，那么改用自定义域名是推荐做法。

通过控制台迁移

以迁移路由 example.com/* 为例：

  1. 在 Cloudflare 控制台打开你域名的 DNS Records 页面。前往 Records ↗
  2. 删除 example.com 的 CNAME 记录。
  3. 进入 Account Home > Workers & Pages。
  4. 在 Overview 中选择你的 Worker > Settings > Domains & Routes。
  5. 选择 Add > Custom domain，添加 example.com。
  6. 在 Worker 的 Settings > Domains & Routes 中删除路由 example.com/*。

通过 Wrangler 迁移

在 Wrangler 配置文件中迁移路由 example.com/*：

  1. 在 Cloudflare 控制台打开你域名的 DNS Records 页面。前往 Records ↗
  2. 删除 example.com 的 CNAME 记录。
  3. 在 Wrangler 文件中加入： 
    {
  "routes": [
    {
      "pattern": "example.com",
      "custom_domain": true
    }
  ]
}
    [[routes]]
pattern = "example.com"
custom_domain = true
  4. 运行 npx wrangler deploy，创建 Worker 将要运行的自定义域名。
