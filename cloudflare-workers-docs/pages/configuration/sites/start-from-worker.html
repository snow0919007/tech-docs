给已有 Worker 加上静态资源

在现有 Worker 里用 getAssetFromKV() 提供静态文件。

配置 原文更新于 2026-04-23 对应页面：configuration/sites/start-from-worker
请改用 Workers 静态资源

托管全栈应用请用 Workers 静态资源，而不是 Workers Sites。Workers Sites 在 Wrangler v4 中已被废弃，Cloudflare Vite 插件也不支持它。新项目不要使用 Workers Sites。

Workers Sites 依赖 Wrangler ↗，请务必使用最新版本。

如果你已有一个 Worker 项目，也可以用 Workers Sites 为它提供静态资源。

开始

  1. 在项目根目录下建一个存放资源的目录（例如 ./public）。
  2. 在 Wrangler 文件里指向该目录： 
    {
  "site": {
    "bucket": "./public" // Add the directory with your static assets!
  }
}
    [site]
bucket = "./public"
  3. 安装 @cloudflare/kv-asset-handler： 
    npm i -D @cloudflare/kv-asset-handler
  4. 在 Worker 入口导入 getAssetFromKV()，用它返回静态资源：
import { getAssetFromKV } from "@cloudflare/kv-asset-handler";
import manifestJSON from "__STATIC_CONTENT_MANIFEST";
const assetManifest = JSON.parse(manifestJSON);

export default {
	async fetch(request, env, ctx) {
		try {
			// Add logic to decide whether to serve an asset or run your original Worker code
			return await getAssetFromKV(
				{
					request,
					waitUntil: ctx.waitUntil.bind(ctx),
				},
				{
					ASSET_NAMESPACE: env.__STATIC_CONTENT,
					ASSET_MANIFEST: assetManifest,
				},
			);
		} catch (e) {
			let pathname = new URL(request.url).pathname;
			return new Response(`"${pathname}" not found`, {
				status: 404,
				statusText: "not found",
			});
		}
	},
};

Service Worker 格式（已废弃，建议迁到模块化 Worker）的等价写法：

import { getAssetFromKV } from "@cloudflare/kv-asset-handler";

addEventListener("fetch", (event) => {
	event.respondWith(handleEvent(event));
});

async function handleEvent(event) {
	try {
		// Add logic to decide whether to serve an asset or run your original Worker code
		return await getAssetFromKV(event);
	} catch (e) {
		let pathname = new URL(event.request.url).pathname;
		return new Response(`"${pathname}" not found`, {
			status: 404,
			statusText: "not found",
		});
	}
}

getAssetFromKV() 的可配置项见 kv-asset-handler 文档 ↗。

最后像平时一样部署：wrangler deploy 或 npx wrangler deploy。Wrangler 会自动上传配置目录里的资源。

npx wrangler deploy
