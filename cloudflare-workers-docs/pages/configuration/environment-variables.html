环境变量

环境变量是一类绑定，用来把文本或 JSON 值附加到 Worker 上。

配置 原文更新于 2026-08-21 对应页面：configuration/environment-variables

背景

你可以添加环境变量（environment variables）——它是绑定的一种——把文本字符串或 JSON 值附加到 Worker 上。环境变量可通过传给 Worker 的 fetch 事件处理器的 env 参数访问。

文本字符串与 JSON 值不加密，适合存放应用配置。

通过 Wrangler 添加环境变量

在 Wrangler 文件里用 [vars] 配置定义文本与 JSON 值。下例中 API_HOST、API_ACCOUNT_ID 是文本值，SERVICE_X_DATA 是 JSON 值。

{
	"$schema": "./node_modules/wrangler/config-schema.json",
	"name": "my-worker-dev",
	"vars": {
		"API_HOST": "example.com",
		"API_ACCOUNT_ID": "example_user",
		"SERVICE_X_DATA": {
			"URL": "service-x-api.dev.example",
			"MY_ID": 123
		}
	}
}
"$schema" = "./node_modules/wrangler/config-schema.json"
name = "my-worker-dev"

[vars]
API_HOST = "example.com"
API_ACCOUNT_ID = "example_user"

  [vars.SERVICE_X_DATA]
  URL = "service-x-api.dev.example"
  MY_ID = 123

在 Worker 代码里这样访问 API_HOST：

export default {
	async fetch(request, env, ctx) {
		return new Response(`API host: ${env.API_HOST}`);
	},
};
export interface Env {
	API_HOST: string;
}

export default {
	async fetch(request, env, ctx): Promise<Response> {
		return new Response(`API host: ${env.API_HOST}`);
	},
} satisfies ExportedHandler<Env>;
from workers import WorkerEntrypoint, Response

class Default(WorkerEntrypoint):
    async def fetch(self, request):
        # Environment variables are accessed via attribute access on self.env
        return Response(f"API host: {self.env.API_HOST}")

导入 env 以便全局访问

你也可以从 cloudflare:workers 导入 env，从而在代码任何位置访问环境变量，包括请求处理器之外：

import { env } from "cloudflare:workers";

// Access environment variables at the top level
const apiHost = env.API_HOST;

export default {
	async fetch(request) {
		return new Response(`API host: ${apiHost}`);
	},
};
import { env } from "cloudflare:workers";

// Access environment variables at the top level
const apiHost = env.API_HOST;

export default {
	async fetch(request: Request): Promise<Response> {
		return new Response(`API host: ${apiHost}`);
	},
};

这种做法适合这些场景：

  • 在 Worker 顶层初始化配置或 API 客户端。
  • 从深层嵌套的函数里访问环境变量，而无需每次调用都传 env。

详见把 env 作为全局导入。

在 Wrangler 中配置不同环境

Wrangler 的环境让你为同一个 Worker 指定不同配置，包括每个环境不同的 vars 取值。由于 vars 属于不可继承的键，它不会被环境继承，必须逐个环境单独指定。

下例建了 staging 与 production 两个环境，API_HOST 取值不同。

{
	"$schema": "./node_modules/wrangler/config-schema.json",
	"name": "my-worker-dev",
	// top level environment
	"vars": {
		"API_HOST": "api.example.com"
	},
	"env": {
		"staging": {
			"vars": {
				"API_HOST": "staging.example.com"
			}
		},
		"production": {
			"vars": {
				"API_HOST": "production.example.com"
			}
		}
	}
}
"$schema" = "./node_modules/wrangler/config-schema.json"
name = "my-worker-dev"

[vars]
API_HOST = "api.example.com"

[env.staging.vars]
API_HOST = "staging.example.com"

[env.production.vars]
API_HOST = "production.example.com"

要在特定环境里运行 Wrangler 命令，加 --env 或 -e 标志。例如在 staging 环境里开发用 npx wrangler dev --env staging，部署用 npx wrangler deploy --env staging。

进一步了解 Wrangler 的环境。

通过控制台添加环境变量

  1. 在 Cloudflare 控制台进入 Workers & Pages。前往 Workers & Pages ↗
  2. 在 Overview 中选择你的 Worker。
  3. 选择 Settings。
  4. 在 Variables and Secrets 下选择 Add。
  5. 选择 Type，填入 Variable name 与 Value。这个变量随后对 Worker 可用。
  6. （可选）要加多个环境变量，选择 Add variable。
  7. 选择 Deploy 生效。
明文与密钥

如果你的环境变量属于密钥，请选择 Secret 类型。账户级密钥也可以考虑 Cloudflare Secrets Store ↗。

密钥与环境变量的区别

敏感信息请用密钥

不要用明文环境变量存放敏感信息。请改用密钥或 Secrets Store 绑定 ↗。

密钥本质上就是环境变量，区别在于：一旦定义，密钥的值在 Wrangler 或 Cloudflare 控制台里就看不到了。也就是说，密码、API 令牌等敏感数据必须加密存放，以防泄漏。对 Worker 而言，环境变量与密钥没有差别——密钥的值会按定义原样传入。

本地开发中的密钥

谨慎

不要在 Wrangler 配置文件的 vars 里存放敏感信息，请改用密钥。

本地开发用的密钥放在 .dev.vars 或 .env 文件里，与 Wrangler 配置文件同目录。

注意

可以用 secrets 配置属性声明 Worker 需要哪些密钥名。一旦声明，只有 secrets.required 里列出的键才会从 .dev.vars 或 .env 加载；多余的键会被排除，缺失的键会给出警告。

注意

.dev.vars 与 .env 只用其一，不要同时用。如果你定义了 .dev.vars，本地开发时 .env 里的值不会进入 env 对象。

这些文件使用 dotenv ↗ 语法。例如：

SECRET_KEY="value"
API_TOKEN="eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9"
不要把密钥提交到 git

.dev.vars 与 .env 不应提交到 git。把 .dev.vars* 和 .env* 加进项目的 .gitignore。

要为每个 Cloudflare 环境设置不同密钥，创建名为 .dev.vars.<environment-name> 或 .env.<environment-name> 的文件。

本地开发时选中某个 Cloudflare 环境后，对应的环境专属文件会先于通用的 .dev.vars（或 .env）被加载。

  • 使用 .dev.vars.<environment-name> 时，所有密钥都必须按环境定义。只要存在 .dev.vars.<environment-name>，就只加载它，.dev.vars 不会被加载。
  • 相反，所有匹配的 .env 文件都会被加载并合并取值。每个变量取最具体的那个文件的值，优先级为：.env.<environment-name>.local（最具体）→ .env.local → .env.<environment-name> → .env（最不具体）。
控制 .env 的加载行为

可以通过在运行工具的进程上设置环境变量，来控制本地开发时 .env 的加载方式。

  • 若没有提供 .dev.vars、且不想从 .env 加载本地开发变量，把 CLOUDFLARE_LOAD_DEV_VARS_FROM_DOT_ENV 设为 "false"。
  • 若想把系统进程环境里的所有环境变量都当作本地开发变量，先确保没有 .dev.vars，再把 CLOUDFLARE_INCLUDE_PROCESS_ENV 设为 "true"。使用 secrets 配置属性时不需要这么做，它会自动从 process.env 加载。

环境变量与 Node.js 兼容性

同时启用 nodejs_compat 与 nodejs_compat_populate_process_env 兼容性标志（兼容性日期为 2025-04-01 及之后时默认启用）后，环境变量可通过全局 process.env 访问。

process.env 会在 Worker 中首次访问 process 时惰性填充。

文本变量的值直接暴露。

求值为字符串值的 JSON 变量，按解析后的值暴露。

求值结果不是字符串值的 JSON 变量，按原始 JSON 字符串暴露。

例如，一个 Worker 有三个环境变量——两个文本值、一个 JSON 值：

[vars]
FOO =  "abc"
BAR =  "abc"
BAZ = { "a": 123 }

环境变量可以通过 wrangler.{json|jsonc|toml} 文件或 Cloudflare 控制台界面添加。

process.env.FOO 与 process.env.BAR 的值都是 JavaScript 字符串 "abc"。

process.env.BAZ 的值是 JSON 编码后的字符串 "{ \"a\": 123 }"。

注意

还要注意，因为在运行时里密钥也是环境变量的一种，所以密钥同样会通过 process.env 暴露。
