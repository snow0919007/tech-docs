Page Rules 与 Workers

命中 Worker 路由后，哪些 Page Rules 会失效、哪些仍生效。

配置 原文更新于 2026-10-28 对应页面：configuration/workers-with-page-rules

当请求匹配你定义的某个 URL 模式时，Page Rules 会触发相应动作。你可以定义一条 Page Rule，让它在匹配到某个 URL 模式时触发一个或多个动作。Page Rules 的配置方式见 Page Rules ↗。

Page Rules 与 Workers 的配合

Cloudflare 作为反向代理 ↗，为各类互联网资产提供 Page Rules 之类的服务。你应用的流量会经过离访问者最近的 Cloudflare 数据中心——全球有数百个，每个都能运行 Workers 与 Page Rules 这类服务。如果你的应用构建在 Workers 和/或 Pages 上，那么 Cloudflare 全球网络 ↗就是你的源站，直接从全球网络回应请求。

把 Page Rules 与 Workers 一起使用时，流程如下：

  1. 请求抵达 Cloudflare 数据中心。
  2. Cloudflare 判断该请求是否属于某条 Worker 路由。由于它是 Worker 路由，Cloudflare 会关闭一批特性——其中一些本应由 Page Rules 设置。
  3. Page Rules 作为常规请求处理的一部分运行，但部分特性已被关闭。
  4. Worker 执行。
  5. Worker 发起同区或其他区的子请求。因为这也是 Worker 路由，Cloudflare 同样关闭一批特性——包括一些本应由 Page Rules 设置的。

也就是说，Page Rules 会在「客户端 → Worker」阶段（第 2 步）与「Worker 子请求」阶段（第 5 步）各被求值一次。

如果运行 Workers 时遇到 Page Rule 报错，请联系你的 Cloudflare 客户团队或 Cloudflare 支持 ↗。

受影响的 Page Rules

当入站请求被匹配到 Worker 路由时，下列 Page Rules 可能不会按预期工作：

  • Always Online
  • Always Use HTTPS
  • Automatic HTTPS Rewrites
  • Browser Cache TTL
  • Browser Integrity Check
  • Cache Deception Armor
  • Cache Level
  • Disable Apps
  • Disable Zaraz
  • Edge Cache TTL
  • Email Obfuscation
  • Forwarding URL
  • Host Header Override
  • IP Geolocation Header
  • Origin Cache Control
  • Rocket Loader
  • Security Level
  • SSL

原因是：一旦 Cloudflare 识别出请求是发往 Worker 的，这些 Page Rules 的默认设置就会被禁用。

测试说明

由于 Workers 运行时仍在持续变化，这些规则受影响的具体说明会在测试之后更新。各规则本身的作用见 Page Rules ↗。

同区与其他区

同区子请求指 Worker 向它所在区域内一个橙云代理的主机名发起的请求。取决于你的 DNS 配置，任何落在这个定义之外的请求，都可能被 Cloudflare 网络视为其他区请求。
