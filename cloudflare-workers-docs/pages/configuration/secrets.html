密钥（Secrets）

把 API key、令牌等敏感信息加密存放，只在运行时交给 Worker。

配置 原文更新于 2026-10-15 对应页面：configuration/secrets

背景

密钥（secrets）是绑定的一种，用来把加密的文本值附加到 Worker 上，用于存放 API key、认证令牌这类敏感信息。

在 Worker 代码里可以通过以下途径访问密钥：

  • 传给 Worker fetch 事件处理器的 env 参数。
  • 从 cloudflare:workers 导入 env，从而在代码任何位置访问。
  • 在启用了 Node.js 兼容性的 Worker 中使用 process.env。

在 Worker 中访问密钥

密钥的访问方式与其他环境变量完全一样。比如有一个 DB_CONNECTION_STRING 密钥，就可以通过 env 参数取到它：

import postgres from "postgres";

export default {
	async fetch(request, env, ctx) {
		const sql = postgres(env.DB_CONNECTION_STRING);

		const result = await sql`SELECT * FROM products;`;

		return new Response(JSON.stringify(result), {
			headers: { "Content-Type": "application/json" },
		});
	},
};

也可以从 cloudflare:workers 导入 env，在代码任何位置（包括请求处理器之外）访问密钥：

import { env } from "cloudflare:workers";
import postgres from "postgres";

// Initialize the database client at the top level using a secret
const sql = postgres(env.DB_CONNECTION_STRING);

export default {
	async fetch(request) {
		const result = await sql`SELECT * FROM products;`;

		return new Response(JSON.stringify(result), {
			headers: { "Content-Type": "application/json" },
		});
	},
};
import { env } from "cloudflare:workers";
import postgres from "postgres";

// Initialize the database client at the top level using a secret
const sql = postgres(env.DB_CONNECTION_STRING);

export default {
	async fetch(request: Request): Promise<Response> {
		const result = await sql`SELECT * FROM products;`;

		return new Response(JSON.stringify(result), {
			headers: { "Content-Type": "application/json" },
		});
	},
};

全局访问 env 的更多细节见把 env 作为全局导入。

本地开发中的密钥

谨慎

不要在 Wrangler 配置文件的 vars 里存放敏感信息，请改用密钥。

本地开发用的密钥放在 .dev.vars 或 .env 文件里，与 Wrangler 配置文件同目录。

注意

可以用 secrets 配置属性声明 Worker 需要哪些密钥名。一旦声明，只有 secrets.required 里列出的键才会从 .dev.vars 或 .env 加载；多余的键会被排除，缺失的键会给出警告。

注意

.dev.vars 与 .env 只用其一，不要同时用。如果你定义了 .dev.vars，本地开发时 .env 里的值不会进入 env 对象。

这些文件使用 dotenv ↗ 语法。例如：

SECRET_KEY="value"
API_TOKEN="eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9"
不要把密钥提交到 git

.dev.vars 与 .env 不应提交到 git。把 .dev.vars* 和 .env* 加进项目的 .gitignore。

要为每个 Cloudflare 环境设置不同密钥，创建名为 .dev.vars.<environment-name> 或 .env.<environment-name> 的文件。

本地开发时选中某个 Cloudflare 环境后，对应的环境专属文件会先于通用的 .dev.vars（或 .env）被加载。

  • 使用 .dev.vars.<environment-name> 时，所有密钥都必须按环境定义。只要存在该文件，就只加载它，.dev.vars 不会被加载。
  • 相反，所有匹配的 .env 文件都会被加载并合并取值。每个变量取最具体的那个文件的值，优先级为：.env.<environment-name>.local → .env.local → .env.<environment-name> → .env。
控制 .env 的加载行为

可以通过在运行工具的进程上设置环境变量，来控制本地开发时 .env 的加载方式。

  • 若没有提供 .dev.vars、且不想从 .env 加载本地开发变量，把 CLOUDFLARE_LOAD_DEV_VARS_FROM_DOT_ENV 设为 "false"。
  • 若想把系统进程环境里的所有环境变量都当作本地开发变量，先确保没有 .dev.vars，再把 CLOUDFLARE_INCLUDE_PROCESS_ENV 设为 "true"。使用 secrets 配置属性时不需要这么做，它会自动从 process.env 加载。

已部署 Worker 上的密钥

部署前校验密钥

可以在 Wrangler 配置中用 secrets 配置属性声明 Worker 所需的密钥名。声明之后，只要有任何必需密钥尚未在 Worker 上配置，wrangler deploy 与 wrangler versions upload 就会直接失败，并给出明确错误。

给项目添加密钥

通过 Wrangler

可以用 wrangler secret put 或 wrangler versions secret put 命令添加密钥。

wrangler secret put 会创建一个新的 Worker 版本并立即部署。

npx wrangler secret put <KEY>

如果你在用渐进式部署，请改用 wrangler versions secret put：它只创建新版本，随后用 wrangler versions deploy 部署。

注意

3.73.0 之前的 Wrangler 版本需要额外加 --x-versions 标志。

npx wrangler versions secret put <KEY>

通过控制台

  1. 在 Cloudflare 控制台进入 Workers & Pages。前往 Workers & Pages ↗
  2. 在 Overview 中选择你的 Worker > Settings。
  3. 在 Variables and Secrets 下选择 Add。
  4. 类型选 Secret，填入 Variable name 与 Value。该密钥随后对 Worker 可用，但其值在 Wrangler 与控制台中都会隐藏。
  5. （可选）要加更多密钥，选择 Add variable。
  6. 选择 Deploy 生效。

随代码一起上传密钥

用 wrangler deploy 或 wrangler versions upload 的 --secrets-file 标志，可以在上传代码的同时上传密钥。它接受 JSON 或 .env 文件路径——与 wrangler secret bulk 接受的格式相同。单个版本的一次批量请求最多可上传 100 个密钥。

npx wrangler deploy --secrets-file .env.production
npx wrangler versions upload --secrets-file secrets.json

文件中未包含的密钥会保留上一版本的值。这在 CI/CD 流水线里很有用——一次操作即可同时部署代码并更新密钥。

删除项目中的密钥

通过 Wrangler

可以用 wrangler secret delete 或 wrangler versions secret delete 删除密钥。

wrangler secret delete 会创建一个新的 Worker 版本并立即部署。

npx wrangler secret delete <KEY>

如果你在用渐进式部署，请改用 wrangler versions secret delete：它只创建新版本，随后用 wrangler versions deploy 部署。

npx wrangler versions secret delete <KEY>

通过控制台

  1. 在 Cloudflare 控制台进入 Workers & Pages。前往 Workers & Pages ↗
  2. 在 Overview 中选择你的 Worker > Settings。
  3. 在 Variables and Secrets 下选择 Edit。
  4. 在 Edit 抽屉里，点要删除的密钥旁边的 X。
  5. 选择 Deploy 生效。
  6. （可选）也可以不用编辑抽屉，直接点密钥旁边的删除图标。

密钥与环境变量的区别

敏感信息请用密钥

不要用明文环境变量存放敏感信息。请改用密钥或 Secrets Store 绑定 ↗。

密钥本质上就是环境变量，区别在于：一旦定义，密钥的值在 Wrangler 或 Cloudflare 控制台里就看不到了。也就是说，密码、API 令牌等敏感数据必须加密存放，以防泄漏。对 Worker 而言，环境变量与密钥没有差别——密钥的值会按定义原样传入。
