Workers 的运行原理

Workers 运行时与浏览器里的 JavaScript、Node.js 有什么不同。

参考 原文更新于 2026-09-18 对应页面：reference/how-workers-works

虽然 Cloudflare Workers 的行为与浏览器里或 Node.js 里的 JavaScript ↗ 很像，但在思考代码的方式上仍有几处不同。在底层，Workers 运行时使用 V8 引擎 ↗——与 Chromium 和 Node.js 相同的引擎；同时它也实现了现代浏览器中常见的大量标准 API。

为浏览器或 Node.js 编写的 JavaScript，与 Workers 的差异出现在运行环境这一层。Workers 函数并不跑在某台个人机器上（例如浏览器应用或集中式服务器 ↗），而是跑在 Cloudflare 的全球网络 ↗上——一张由数千台机器组成、分布在数百个地点的、仍在扩张的网络。

这些机器每一台都承载一个 Workers 运行时实例，而每个运行时都能同时运行成千上万个用户定义的应用。本文梳理其中几处关键差异。

更多背景可参考 《Cloud Computing without Containers》↗ 一文。

最大的三处差异是：Isolate（隔离实例）、按请求计算、分布式执行。

Isolate

V8 ↗ 负责调度 isolate：这是一种轻量上下文，为你的代码提供可访问的变量，以及一个可安全执行的环境。你完全可以把 isolate 理解成让你的函数运行的沙箱。

一个运行时实例可以运行成百上千个 isolate，并在它们之间无缝切换。每个 isolate 的内存完全隔离，因此每一段代码都受到保护，不会被运行时上其他不可信或用户编写的代码影响。isolate 的启动也非常快：它不是为每个函数新建一台虚拟机，而是在已有环境内部创建。这一模型消除了虚拟机模型里的冷启动（cold start）问题。

其他无服务器服务商通常使用容器化进程 ↗，每个进程跑一个语言运行时实例。而 Workers 只需在容器启动时支付一次 JavaScript 运行时的开销，之后各个 Workers 进程几乎不产生单实例开销，能运行数量近乎无限的脚本。任何一个 isolate 的启动速度，都可以比容器或虚拟机上的 Node 进程快约一百倍；更值得注意的是，启动时 isolate 占用的内存要低一个数量级。

原站示意图

原文此处配有一张「传统架构 vs Workers V8 isolates」的对比图（用户代码与进程开销的分层示意）。本译文以文字保留其结论：传统架构中每个请求都背着一层进程开销，而 isolate 模型把这层开销摊薄到几乎可以忽略。

一个 isolate 有自己的作用域，但并不一定长期存活。它可能因为若干原因被回收、被驱逐：

  • 机器资源受限。
  • 脚本可疑——例如有任何试图突破 isolate 沙箱的行为。
  • 触碰到单项资源限额。

因此在全局作用域里保存可变状态一般不被推荐，除非你已经针对这种情况做了兜底处理。

如果你关心 Cloudflare 在 Workers 运行时上如何处理安全问题，可以进一步阅读Isolate 与安全、Spectre 威胁缓解的关系。

按请求计算

大多数 Worker 都是默认流程的变体：

export default {
	async fetch(request, env, ctx) {
		return new Response('Hello World!');
	},
};
export default {
	async fetch(request, env, ctx): Promise<Response> {
		return new Response('Hello World!');
	},
} satisfies ExportedHandler<Env>;

对于用 ES modules 语法编写的 Worker：当发往你的 *.workers.dev 子域或 Cloudflare 托管域名的请求抵达 Cloudflare 的任一数据中心时，这个请求会调用你在 Worker 代码中定义的 fetch() 处理器；你通过返回一个 Response 对象来响应它。

分布式执行

isolate 具备韧性，在一次请求期间持续可用；但在极少数情况下，isolate 仍可能被驱逐。当 Worker 触达官方限额，或请求所在机器的资源异常紧张时，运行时会在这批事件被妥善处理完之后，有选择地驱逐 isolate。

与其他所有 JavaScript 平台一样，单个 Workers 实例可以在单线程事件循环中处理多个请求（包括并发请求）。这意味着：在处理某个请求期间，如果有其他请求进来，那些请求可能会（也可能不会）在你 await 某个 async 任务（例如 fetch）时被处理。由于无法保证任意两个用户请求会被路由到同一个或不同的 Worker 实例，Cloudflare 建议不要使用或修改全局状态。
