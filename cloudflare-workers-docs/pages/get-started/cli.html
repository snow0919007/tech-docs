通过 CLI 创建（Wrangler）

用 Cloudflare 开发者平台的命令行工具 Wrangler，搭建并部署你的第一个 Worker。

快速开始 原文更新于 2026-10-12 对应页面：get-started/guide

本指南带你一步步完成第一个 Worker 的搭建与部署。

前置条件

  1. 注册一个 Cloudflare 账号 ↗。
  2. 安装 Node.js ↗。
Node.js 版本管理器

可以用 Vite+（vp env）↗ 安装和管理 Node.js 版本。

受支持的 Node.js 版本范围，请参见 Wrangler 系统要求。

1. 创建新的 Worker 项目

打开终端，运行 C3 来创建 Worker 项目。C3（create-cloudflare-cli）↗ 是一个命令行工具，用来帮你在 Cloudflare 上搭建并部署新应用。

npm create cloudflare@latest -- my-first-worker
yarn create cloudflare my-first-worker
pnpm create cloudflare@latest my-first-worker

初始化时，按下面这样选择：

  • What would you like to start with?（从哪里开始）→ 选 Hello World example。
  • Which template would you like to use?（用哪个模板）→ 选 Worker only。
  • Which language do you want to use?（用哪种语言）→ 选 JavaScript。
  • Do you want to use git for version control?（是否用 git 做版本控制）→ 选 Yes。
  • Do you want to add an AGENTS.md file to help AI coding tools understand Cloudflare APIs?（是否添加 AGENTS.md 帮助 AI 编码工具理解 Cloudflare API）→ 选 Yes。
  • Do you want to deploy your application?（是否立即部署）→ 选 No（我们打算先改点东西再部署）。

现在新项目已经建好，进入项目目录：

cd my-first-worker
C3 生成了哪些文件？

在你的项目目录里，C3 会生成：

  • wrangler.jsonc：你的 Wrangler 配置文件。对于 JavaScript 和 TypeScript 项目，C3 会开启 source map 上传，使捕获到的异常堆栈指向你的原始代码。
  • index.js（位于 /src）：一个最小的 'Hello World!' Worker，使用 ES module 语法编写。
  • package.json：最小的 Node 依赖配置文件。
  • package-lock.json：参见 npm 关于 package-lock.json 的文档 ↗。
  • node_modules：参见 npm 关于 node_modules 的文档 ↗。
我已经有一个 Git 仓库里的项目，怎么办？

除了从 C3 模板创建新项目，C3 也支持基于已有的 Git 仓库创建项目。打开终端运行：

npm create cloudflare@latest -- --template <SOURCE>

<SOURCE> 可以是以下任一形式：

  • user/repo（GitHub）
  • git@github.com:user/repo
  • https://github.com/user/repo
  • user/repo/some-template（子目录）
  • user/repo#canary（分支）
  • user/repo#1234abcd（提交哈希）
  • bitbucket:user/repo（Bitbucket）
  • gitlab:user/repo（GitLab）

要满足 Cloudflare Workers 的要求，你现有的模板目录至少需要包含这些文件：

  • package.json
  • wrangler.jsonc（查看 Wrangler 配置示例）
  • src/，其中包含一个由 wrangler.jsonc 引用的 worker 脚本

2. 用 Wrangler CLI 开发

C3 默认会在 Workers 项目里安装 Wrangler——Workers 的命令行工具。Wrangler 让你能够创建、测试和部署 Workers 项目。

第一个 Worker 建好之后，在项目目录中运行 wrangler dev，即可启动本地服务器来开发你的 Worker。开发期间可以在本地预览效果。

npx wrangler dev

如果你是第一次使用 Wrangler，它会打开浏览器让你登录 Cloudflare 账号。

访问 http://localhost:8787 ↗ 查看你的 Worker。

浏览器打不开？

如果这一步出问题，或者你无法使用浏览器界面，请参考 wrangler login 的文档。

3. 写代码

项目已生成并跑起来了，现在可以开始编写和修改代码。

找到 src/index.js 文件，里面的内容如下：

export default {
	async fetch(request, env, ctx) {
		return new Response("Hello World!");
	},
};
代码讲解

这段代码由几个部分组成。

export default 是定义 JavaScript 模块 ↗ 所必需的语法。你的 Worker 必须默认导出一个对象，其属性对应 Worker 需要处理的事件。

这个 fetch() 处理器会在 Worker 收到 HTTP 请求时被调用。你可以在导出对象里定义更多事件处理器，以响应不同类型的事件。比如添加一个 scheduled() 处理器，来响应用 Cron 触发器发起的调用。

此外，fetch 处理器始终会收到三个参数：request、env 和 context。

Workers 运行时要求 fetch 处理器返回一个 Response 对象，或一个 resolve 为 Response 对象的 Promise。在这个例子里，返回的是包含字符串 "Hello World!" 的新 Response。

把 index.js 里的内容替换为下面这段，输出文字就变了：

export default {
	async fetch(request, env, ctx) {
		return new Response("Hello Worker!");
	},
};

保存文件并刷新页面，Worker 的输出就会变成新的文字。

看不到变化？

如果 Worker 的输出没有变化，确认以下几点：

  1. 改动确实保存到了 index.js。
  2. wrangler dev 正在运行。
  3. 你刷新了浏览器。

4. 部署项目

通过 Wrangler 把 Worker 部署到 *.workers.dev 子域或自定义域名：

npx wrangler deploy

如果你还没有配置任何子域或域名，Wrangler 会在发布过程中提示你设置一个。

然后访问 <YOUR_WORKER>.<YOUR_SUBDOMAIN>.workers.dev 预览你的 Worker。

遇到 523 错误？

如果你是第一次推送 *.workers.dev 子域并看到 523 错误，等一两分钟，错误会自行消失。

下一步

还可以做这些事：

  • 把项目推送到 Artifacts、GitHub 或 GitLab 仓库，然后接入构建，启用自动构建与部署。
  • 打开 Cloudflare 控制台 ↗ 做更轻量的编辑。
  • 浏览示例与教程找灵感。
  • 配置绑定，让 Worker 能与其他资源交互、解锁新能力。
  • 学习如何测试与调试你的 Worker。
  • 了解 Workers 的限额与计费。
